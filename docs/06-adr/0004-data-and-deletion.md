# ADR-0004：数据与删除策略（本机 SQLite、两状态、24h 物理删除）

- 状态：Accepted
- 日期：2026-11-01
- 关联：`00-product-decisions.md` §2/§4；`03-domain-model.md`；`05-contracts/storage-schema.md`

## 背景

产品要求极简与"永远清晰"：没有收件箱、标签、多状态；已完成 24h 后彻底消失。用户明确：**不做数据备份与导出**，删除不可恢复。

## 决策

- 数据只存本机 **SQLite**（rusqlite，WAL）。
- 事件只有两个状态：未完成 / 已完成（用 `completed_at` 表达，不存状态枚举）。
- 已完成项在所有视图底部折叠，24 小时内可恢复；**24 小时后物理删除**。
- 重复任务：完成只删"本次"，事件系列保留并计算下一次；本次完成记录 24h 后物理删除。
- 计数任务：`progress` + `period_key`，周期边界（每天零点/每周一）清零；完成状态在边界消失。
- 删除操作在详情抽屉中执行，**永久删除、不可恢复**。
- **不做备份、不做导出、不做回收站**；不做系统通知。
- 数据丢失风险必须在隐私/说明位置明确告知（具体位置待定）。

## 后果

- 正面：数据模型极简、隐私最小化、界面清晰、无同步/账号负担。
- 负面：误删/换机/磁盘损坏无法找回；用户需自行承担；无法做数据迁移。
- 若未来要备份/导出/同步，需要重新评估并新增 ADR。

## 备选

软归档/回收站/自动备份：用户已明确否决。
