# ADR-0001：AI 能力的提供方式（官方网关 + BYOK + 规则模式）

- 状态：Accepted
- 日期：2026-11-01
- 关联：`00-product-decisions.md` §9；`05-contracts/gateway-api.md`

## 背景

产品约束是"用户不需要部署任何服务器"；同时希望"任何安装的人都能用上 AI"。若把 API Key 放进客户端，会被抓包/调试提取，导致盗刷与封号；若由作者内置统一 Key，则必须自建代理做鉴权、限额与计费。

## 决策

采用三种 AI 模式，客户端抽象为 `AiService`：

1. **官方网关（默认）**：客户端只持有激活码 + 设备 ID，调用作者部署在阿里云函数计算的轻量网关；厂商 Key 只存在网关环境变量。
2. **BYOK（兜底/高级）**：用户在设置里填自己的供应商 base URL / Key；Key 存 Windows 凭据管理器，不写配置文件、不打日志。
3. **规则模式（离线降级）**：无网络/无激活码/额度用尽时，仅用本地规则（时间词典、简单重复、动作标题）解析；原文进收件箱改为"无字段事件"直接创建，绝不丢输入。

网关提供 `/v1/health`、`/v1/transcribe`、`/v1/parse` 三个接口，配额为每设备每日 200 次 + 月预算 ¥200 告警。

## 后果

- 正面：客户端无厂商 Key；用户零配置（只需激活码）；成本与滥用可控；可随时切换供应商。
- 负面：作者需维护网关与支付；用户依赖网络；公开分发涉及合规（延后评估）。
- 客户端必须有完整的失败降级与配额提示。

## 备选

- 全本机模型：效果/体积/CPU 体验不达标，已否决。
- 客户端内置作者 Key：Key 无法保密，否决（仅自用可临时采用）。
- 纯 BYOK：不满足"零配置"，但保留为兜底模式。
