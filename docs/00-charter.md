## 1. 一句话

**Clarify 是一个不用部署服务器、以"说一句就安排好"为核心的 Windows 桌面待办软件：说一句 → 云端识别 + DeepSeek 解析成动作与字段 → 直接落到视图 → 点一下完成 → 24 小时后物理消失。**

## 2. 产品主张（不可妥协）

1. **零决策捕捉**：捕捉只做一个动作（说/写），其余交给默认；绝不在捕捉时弹确认。
2. **不猜**：AI 只提取明确说出的内容；模糊时间不解析、不补默认、不追问。用户自己说清楚。
3. **只有两种状态**：未完成 / 已完成；"逾期/今天/以后"只是视图分组。
4. **清晰是规则**：已完成在所有视图底部折叠，24h 内可恢复，之后**物理删除**；无收件箱、无标签、无项目、无优先级。
5. **无服务器、数据在手**：无自建后端；数据只存本机 SQLite；官方 AI 走轻量网关；无通知、无备份导出、无首启引导。

## 3. 产品硬规则

1. 事件 = **动作标题**（AI 改写，不是原话）+ 可选字段：时间（仅日期/日期+时刻/时段，允许时段+截止）、重复、计数目标（次数+周期）、创建时间、完成时间；不存"类型"枚举。
2. 显示模板只有 **A 时间轴 / B 清单**；A 主窗一天/7天/日历、悬浮窗仅一天（时间范围可配，主窗与悬浮窗各一套）；B 可切今天/全部。
3. 主窗口 = **一个主页面 + 设置**；点行 = 右侧详情抽屉；行首圆圈 = 完成；日历点某天 = 弹当天清单。
4. 悬浮窗 = 独立可移动、可缩放、精致小组件；只有"进入软件首页"图标；点任务 = 完成。
5. 已完成折叠在所有视图底部；24h 内可恢复；之后物理删除；删除操作永久不可恢复。
6. 重复任务只删"本次"，系列保留并计算下一次；计数任务按周期边界清零（每天零点/每周一边界）。
7. **不做**：收件箱、标签、项目、优先级、提醒字段、系统通知、首次引导、备份/导出、回收站、云同步、账号、遥测。

## 4. 用户与核心场景

- **用户**：25~40 岁知识工作者，Windows 笔记本，事情多且碎片化，整理成本高于收益。
- **场景 1**：开会/写代码时想起一件事 → 快捷键说一句 → 回到手上的事。
- **场景 2**：悬浮窗就是"今天的台面" → 看一眼 → 点掉一件。
- **场景 3**：打开主窗口切 A/B 视图，按天/周/月看安排，点行改细节。
- **场景 4**：纯打字建待办；重复/计数类打卡。

## 5. 成功指标（v1 目标）

| 指标 | 目标 |
|---|---|
| 热键 → 捕捉条出现 | < 150 ms |
| 10s 语音端到端（转写+解析+出现） | ≤ 4s P95（正常网络） |
| 动作标题保真 / 时间字段准确率 | 评估集 ≥90%，幻觉 0 |
| JSON 合法率 | ≥99% |
| 单次捕捉 AI 成本 | < ¥0.02 |
| 崩溃/无响应率 | < 0.5% 会话 |
| 创建/清理决策点 | 0 次 |

## 6. 范围（v1）

**做**：F1 捕捉（语音/文字）、F2 AI 解析（动作化/拆条/只取明确）、F3 事件字段与编辑、F4 完成/恢复、F5 重复、F6 计数、F7 A 时间轴、F8 B 清单、F9 悬浮窗、F10 设置、F11 官方 AI 服务（激活/额度/BYOK/规则兜底）、F12 本地数据与物理删除。

**不做**：N1 收件箱、N2 标签/清单/项目、N3 优先级/置顶、N4 提醒字段与系统通知、N5 首次引导、N6 备份/导出/回收站、N7 云同步/账号、N8 团队协作、N9 移动端、N10 日历双向同步、N11 自定义字段、N12 AI 聊天/写操作、N13 多语言界面（v1 中文）、N14 崩溃上报/遥测、N15 公开分发合规体系（延后）。

阶段：内测（自用+≤20 人）→ 公开分发（合规评估后）→ 远期。

## 8. 术语表（v1.1）

| 术语 | 定义 |
|---|---|
| 事件 / Event | 唯一实体：动作标题 + 可选时间/重复/计数目标 |
| 未完成/已完成 | 仅有的两种状态；用 `completed_at` 表达 |
| 完成折叠 | 已完成项显示在所有视图底部，24h 内可恢复 |
| 物理删除 | 完成满 24h 后从数据库删除；删除操作不可恢复 |
| 动作标题 | AI 改写出的"要做什么"，不是原始语音文本 |
| 时间三精度 | 仅日期 / 日期+时刻 / 时段（开始–结束） |
| 重复 | 周期性系列；完成的是本次，系列保留 |
| 计数目标 | 次数+周期（如每天 3 杯）；按周期边界清零 |
| 模板 A / B | A 时间轴、B 清单；只决定摆法 |
| 视图 | 模板 + 范围（今天/全部/一天/7天/日历）+ 分组排序 |
| 悬浮窗 | 独立、可移动、可缩放的小组件 |
| 官方网关 | 部署在云函数的轻量 AI 转发服务，持有厂商 Key |
| 激活码 | 使用官方服务的凭据 |
| BYOK | 用户自带 API Key 的模式 |
| 规则模式 | 无 AI 时的本地规则兜底 |
| 额度 | 每设备每日 200 次 + 月预算 ¥200 |
| 评估集 | `docs/eval/` 62 条中文口语 + 期望 JSON |
| Spike | 允许丢弃代码的短期可行性验证 |
| ADR | 架构决策记录（`06-adr/`） |
| DoR / DoD | 开工标准 / 完成标准 |
| M0~M4 | 开发前准备 / 后端底层 / 主窗悬浮窗 / AI 联调 / 打磨内测 |

## 10. 协作规则

- 单一事实源：同一事实只在一处定义，其余链接引用。
- 改行为必改文档；PR 未同步文档不合并。
- ADR：架构/依赖/契约/成本决策必须记录（背景/选项/决定/后果）。
- 文档 v0.1 → 红队审查 → 冻结；无 Owner 的 TBD 不得存在。
- 秘密管理：真实 Key/激活码一律不进仓库；日志脱敏。
- 每阶段一次红队审查；P0 全关才可进下一阶段。

## 11. 假设与开放项

- 1 名开发 + AI 代理；无专职设计/QA。
- Windows 优先，macOS 延后；先自用+≤20 人内测。
- 用户接受两家 AI 账号（ASR+DeepSeek）与月预算 ¥200。
- 隐私告知位置、AI 解析失败兜底、原文留存、悬浮窗规格、DB 路径等开放问题见 `01-prd.md §8` 决策台账，M0-03 前关闭。
