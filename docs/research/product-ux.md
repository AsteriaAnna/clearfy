# Clarify 产品与交互设计研究报告

> 范围：Windows 桌面端的「本地优先 + 零决策捕捉 + 常驻悬浮窗」。方法：公开产品资料 + 成熟模式拆解，所有结论落到可实现的产品/交互决策。标注「建议后续验证」的条目需用原型或用户测试确认。

## 1. 先例拆解

只取与本产品最相关的 1–2 个模式。

| 产品 | 借鉴 | 避免 |
|---|---|---|
| [Todoist](https://www.todoist.com/help/todoist/features/schedule-a-date-and-time-for-your-todoist-tasks-q7VobO) | 输入时用高亮即时识别自然语言日期，并可点掉误识别；识别"不确定"时给用户一次低成本纠正 | 识别结果埋在设置里、用户看不到模型假设 |
| [TickTick](https://help.ticktick.com/) | 桌面便签/小组件常驻、快捷入口；多视图让同一批任务适配不同场景 | 功能面板持续膨胀（番茄、习惯、矩阵、倒计时），与"极简"冲突 |
| [Things 3](https://culturedcode.com/things/support/articles/6378414/) | Inbox 收纳一切、快速入口（Ctrl+Space）不打断当前工作；Today 是手动承诺而非算法分配 | Area/Project/Heading 概念多，上手成本高；Clarify 不做层级 |
| [Apple 提醒事项](https://support.apple.com/guide/reminders/welcome/mac) | 系统级提醒可靠、列表结构极简、与系统通知整合 | 依赖账号/云；设置项过多，普通用户只用到 20% |
| [Notion](https://www.notion.com/help/reminders) | `@remind` 行内创建提醒，任务与上下文写在同一处 | 把待办做成数据库：属性、视图、模板都需要配置，违背零决策 |
| [Superlist](https://www.superlist.com/) | 任务+笔记混合、条目内可承载上下文 | "瑞士军刀"定位；团队协作功能对个人本地工具是干扰 |
| [Amie](https://amie.so/) | 刘海/悬浮录音浮层 + 一键把行动项加入日程；捕捉发生在"当下场景" | AI 自动重排日历（会打乱用户已确认的计划），Clarify 不做自动挪期 |
| [Sunsama](https://www.sunsama.com/) | Daily Shutdown：一天结束时总结完成项、规划明天，制造"结束感" | 需要每天 10–15 分钟仪式，对懒人过重；Clarify 用自动摘要替代 |
| [Motion](https://www.usemotion.com/) / [Reclaim](https://help.reclaim.ai/en/articles/16995155-agents-overview-automate-smart-calendar-events) | "默认帮你排好"的产品直觉；规则化 Agent 让用户只定策略 | 用户失去控制感、拖拽被自动覆盖；Clarify 默认值必须可一键改且不自动改 |
| [AudioPen](https://www.audiopen.ai/) | 语音→结构化文本，保留转写原文可回看；"先有草稿再润色" | 默认把口语润色成文章；Clarify 需要 JSON 任务而非长文 |
| [Voicenotes](https://voicenotes.com/) | 一键录音、结束后自动出摘要与待办 | 以会议记录为中心、云依赖；本地工具应默认不联网 |
| [Braintoss](https://braintoss.app/) | 单按钮"发给自己"的最低摩擦捕捉 | 只落邮箱、无结构化，之后仍需人工整理 |
| [Mem](https://mem.ai/) | AI 自动归类、减少手动整理 | 信息架构不可预测，用户找不到东西 |
| Windows 待办小组件 / [Rainmeter](https://www.rainmeter.net/) | 高可见性常驻、桌面即界面（[Win11 小组件体验](https://www.makeuseof.com/windows-11-widget-to-do-list-check/)） | 可定制性成本高、易变成"皮肤玩具"；Clarify 只给 5 种预设、不开放皮肤 |

**四个关键模式的共性结论：**
- **零确认捕捉**：Todoist 智能识别、Things 快速入口、Braintoss 单键的共同点是"先落库、后整理"——确认动作从创建时挪到消费时（在悬浮窗里行内改），而不是创建时弹框。
- **悬浮/桌面组件**：常驻不等于打扰，靠"小 + 可穿透 + 可隐藏"；最大失败模式是组件逐渐长成第二个主界面。
- **清空感**：Sunsama 的收工仪式、Things 的完成动画说明——用户要的不是"删除"，而是**视觉上消失**；同时需要一个可回看的"已完成"安全网（Todoist 的已完成列表）。
- **AI 解析兜底**：AudioPen/Voicenotes 都保留转写原文。Clarify 应把原文当唯一真相，AI 结果只是可重算的增量。

## 2. 待办实体模型与状态机

**单一实体 `Task`，用字段派生"类型"，不建四张表。** 最小字段：`id / title / raw_text / notes / due_at / due_type(date|datetime|none) / remind_at / recurrence / tags[] / pinned / status / created_at / completed_at / batch_id / source(voice|text) / parse_confidence`。

派生规则（不新增表、不新增用户决策）：
- 无日期 → 视为"想法/收件箱条目"；只有日期无时间 → "提醒"（当天出现，不精确报时）；有 `remind_at` → 到点通知；有 `recurrence` → 重复任务。
- "等待他人"**不做状态，做标签**（`#等待`）。理由：单用户本地、状态每多一个就多一次选择；等待本质是延期原因，过滤即可。

**状态机（4 态，唯一）：**
```
inbox --(安排日期/置顶)--> todo --(完成)--> done --(24h)--> archived
  ^                          |                 |
  |                          +--(清空日期)----> inbox
  +------(恢复)--------------+<--(撤销 10s / 已完成页 30 天)---+
```

- **重复任务与"完成"**：默认"完成本次"并静默生成下一次，**绝不弹"本次/整个系列"对话框**；完成瞬间在条目位置显示"下一次：周三 9:00"2 秒；长按或右键「结束重复」；删除重复任务才需要一次确认（唯一破坏性操作）。RRULE 只支持 `FREQ / INTERVAL / BYDAY / UNTIL` 子集。
- **24 小时后清除 = 软归档**：完成时写 `completed_at`，各视图过滤；"已完成"页默认保留 30 天可一键恢复；物理删除在 30 天后（设置可选 7/30/永不/立即）。硬删除的代价是几乎不可逆、无统计、备份失效；软归档的代价是隐私残留与 DB 膨胀——用"立即永久删除"和定期 `VACUUM` 兜底。撤销窗口：完成后 10 秒 toast + 已完成页 30 天内恢复。
- **逾期 = 派生视图，不是状态**：`due_at < now && status = todo`。呈现为今天视图顶部"已逾期"分组（最多 3 条，其余折叠）；不用红色警报，用中性文字"逾期 2 天"；不逐条推送惩罚式通知。
- **优先级：v1 不保留数字优先级**，只保留二元「置顶」（最多 3 条），影响悬浮窗排序与今日顶部。理由：P0–P4 是纯决策负担且单用户场景收益低；若后续验证确有需要（建议后续验证），以标签形式加回。

## 3. 语音捕捉关键链路

**交互状态机**（默认热键 `Ctrl+Alt+Space`，按住说话、松开结束；可改）：

| 状态 | 触发 | 界面 | 失败/边界处理 |
|---|---|---|---|
| idle | 按下热键 | 屏幕底部胶囊浮层，波形 + "松开发送 · Esc 取消" | 按压 <300ms 视为误触，静默取消，不建任务 |
| recording | 松开 / 60s 上限 | 胶囊转"转写中"；**占位卡片已创建**（乐观 UI） | 麦克风被占用/权限拒绝：胶囊就地显示原因 + 「打开设置」 |
| transcribing | 本地 ASR | 占位卡片标题 = 转写文本，右上"解析中"微光 | ASR 失败：保留录音 + 「重试 / 手写」两按钮，不丢数据 |
| parsing | 本地 LLM | 卡片**原地升级**（日期 chip、标签 chip 出现，无页面跳转） | 解析失败/非法 JSON：保留原文入收件箱，toast"已存到收件箱，稍后可加时间"，不弹框 |
| created | 解析成功 | toast「已创建 · 明天 20:00」+ 撤销按钮（5s）；对应悬浮窗视图插入 | 多任务：toast「已创建 3 条」+ 一键「合并为一条」 |
| cancelled | Esc / 再按热键 | 胶囊消失，丢弃录音 | 不建条目、不留垃圾 |

**延迟与乐观 UI**：热键→胶囊 <100ms；松开→转写上屏 <800ms；解析完成 <2s（30 字内）。冷启动模型加载 1–3s 时胶囊显示"唤醒中"，此时仍可继续说话。**原则：文本先上屏、结构后补齐，任何阶段中断都不能丢用户的话。**

**"离线"在本产品里不是网络问题**：完全本地意味着断网也能用；真正需要设计的是"模型未就绪"（首次未下载/更新中/文件损坏）——胶囊提示"语音模型未就绪"，本次降级为手写并给下载入口，而不是报"网络错误"。热键被其他软件占用时，首次冲突即在设置页提示重新录制热键。

**"零决策"与"解析会出错"如何共存（核心设计）：**
1. **默认值可视化**：卡片上直接显示 `明天 20:00` `#家`，点击即改——用户看得见 AI 的假设，就不需要确认框。
2. **一键修正**：行内相对日期 chips（今天/明天/下周一/今晚/无日期），改一次即可，不用打开详情。
3. **撤销**：5–10s toast + 全局 `Ctrl+Z`（最近一次创建）+ 已完成/最近页可回改。
4. **低置信度降级**：`confidence < 0.6` 时不设 `due`、进收件箱、不打扰；只在卡片角落留一个"未识别时间"的灰字。
5. **本地学习**（建议后续验证）：记录用户修正过的表达→结果映射，作为本地 few-shot 偏好，不联网。
6. **原文是真相**：每条任务保存 `raw_text`，模型升级后支持"重新解析"，但只提示、不自动改。

**多任务拆分**：一次捕捉生成同 `batch_id` 的 2–5 条；悬浮窗内用细线分组；拆分置信度 <0.6 时合并为一条保留原文（宁少拆、勿乱拆）。

## 4. 悬浮窗

定位：悬浮窗不是"小组件"，而是 Clarify 的**消费界面**；主窗口用于管理，悬浮窗用于看一眼、点一下。

| 显示方式 | 信息层级 | 适用场景 | 容量 |
|---|---|---|---|
| 今日清单（默认） | 日期标题 > 任务（checkbox + 标题 + 时间 chip）> 底部 `＋`/`🎤` | 90% 用户 | 3/5/7 可调，默认 5 |
| 下一条 | 最大字号标题 > 时间/清单 > 下下一条 40% 透明度 | 专注、拖延、番茄 | 1 + 1 |
| 收件箱 | "待整理 N" > 3 条无日期任务 > 「全部」 | GTD 式整理习惯 | 3 |
| 时间轴 | 当前时间指针 > 今天剩余带时间条目 > 下一空档 | 会议多的人 | 4 |
| 自定义清单 | 清单/标签名 > 条目 | 项目型用户 | 5 |
| 极简计数 | "3 / 7" + 一条下一条 | 极简主义、屏幕角落 | 1 |

**通用规格（建议默认值）：**
- 尺寸：320×220 默认，宽度 240–480 可调，高度自适应，最高不超过屏高 60%；极简计数 140×44。
- 位置/多显示器：默认主屏右侧贴边垂直居中；按「显示器 ID + 归一化坐标」记忆；显示器拔插后兜底回主屏。
- 透明度：三档 100/90/75%；鼠标悬停临时 100%，移开 3s 恢复；不提供无级滑杆（防止调成看不清）。
- 置顶与焦点：默认始终置顶但**不抢焦点**（no-activate）；全屏应用/演示时自动隐藏（可关）。
- 点击穿透：默认关闭；「锁定显示」模式开启穿透，仅悬停或热键响应，并提供 3 秒预览。
- 贴边吸附/拖动：距屏幕边缘 <24px 吸附；拖动时半透明预览；双击空白回默认位；位置写入设置。
- 置顶限制：不允许盖住任务栏和系统托盘区域（避免"永远在最上层"的失控感）。
- 条目操作：**单击 checkbox = 完成（唯一主操作）**；悬停出现「推迟 / 编辑 / 打开」；右键菜单（推迟到今天/明天/下周、设提醒、删除、打开主窗）；标题双击行内编辑。
- 创建入口建议：**语音原地 + 文本跳主窗**。悬浮窗常驻 `🎤`（按下即录，不切窗，"说一句"才算零决策）；`＋` 唤起主窗口输入页并聚焦（文本需要编辑空间）。**不建议悬浮窗内联迷你文本输入**：空间小、易误触、无法编辑解析结果。
- 「清晰规则」：每屏 ≤5 条；分组 ≤2 组（"今天/逾期"或"现在/之后"）；溢出显示"+N · 打开工作台"；单条标题 ≤2 行；空状态给正向文案 + 一个示例；禁止红点、角标、优先级色块、任何非任务内容；完成后 1s 内上移淡出。

## 5. 主窗口

**页面地图（一级 6 项，无嵌套）：** 工作台（今日进度 + 下一条 + 收件箱待整理数）｜收件箱｜全部｜已完成｜悬浮窗｜设置。v1 不做全局搜索（本地数据量小），用 Ctrl+F 在"全部"页内过滤即可。

| 页面 | 关键按钮 | 快捷键 |
|---|---|---|
| 全局 | 语音捕捉、新建、撤销、设置 | `Ctrl+Alt+Space` / `Ctrl+N` / `Ctrl+Z` / `Ctrl+,`；切页 `Ctrl+1..6`；关层 `Esc`；帮助 `F1` |
| 工作台 | 开始语音、快速新建、去收件箱整理、悬浮窗预览 | `Enter` 打开下一条 |
| 收件箱 | 逐条「今天 / 明天」、Shift 多选批量安排、「全部转入今日」 | `J/K` 移动，`T` 今天，`M` 明天 |
| 全部 | 按日期分组、筛标签、置顶 | `P` 置顶 |
| 已完成 | 恢复、永久删除、按日分组 | `Delete` 永久删除 |
| 悬浮窗 | 6 种样式切换、位置/透明度/穿透设置、1:1 实时预览 | — |
| 设置 | 通用（开机自启/语言/主题）；捕捉（热键/录音上限/麦克风）；AI（模型状态/重新下载/解析敏感度）；提醒（免打扰时段/每日摘要）；数据（备份/导出/清空）；关于 | — |

**首次运行（目标 <90 秒，5 步）：** ① 欢迎页 + 一句理念 + "数据只在本机"；② 模型下载（显示体积与进度，可跳过——跳过则语音禁用、手写可用）；③ 快捷键教学（必须实际按一次热键才通过）；④ 试说一句（预置 3 条示例，麦克风不可用可跳过）；⑤ 完成时悬浮窗已出现在屏幕右侧并高亮 3 秒，让用户第一眼看到成果。

## 6. AI JSON 契约草案

```json
{
  "version": "1.0",
  "transcript": "明天下午三点提醒我给妈妈打电话，对了周五前把周报发出去",
  "batch_id": "cap_01J...",
  "latency_ms": 1420,
  "tasks": [{
    "title": "给妈妈打电话",
    "notes": null,
    "due": {"type": "datetime", "value": "2026-11-02T15:00:00+08:00", "timezone": "Asia/Shanghai"},
    "due_type": "datetime",
    "remind_at": "2026-11-02T15:00:00+08:00",
    "recurrence": null,
    "tags": ["家"],
    "pinned": false,
    "confidence": 0.92,
    "needs_review": false,
    "assumptions": ["未说年份，默认今年", "未说提醒提前量，默认准点"],
    "source_span": "明天下午三点提醒我给妈妈打电话"
  }]
}
```
约束：`due.type` 只允许 `date|datetime|none`；`value` 必须带时区偏移；`recurrence` 只允许 RRULE 子集或 null；`confidence ∈ [0,1]`；`needs_review` 仅在多任务边界模糊或时间表述冲突时为 true（true 也不弹框，只是卡片加一枚灰点）；单次最多 5 条任务。

**失败模式与兜底：** 非法 JSON/缺字段 → 重试 1 次后降级为"1 条原文任务"；幻觉日期（说了"下周"却给出具体日）→ 用 `assumptions` 暴露依据；拆分过度/不足 → 以 `source_span` 校验覆盖率，覆盖不全则不拆；无意义语音（"今天天气不错"）→ 仍建"想法"进收件箱，不丢弃；超长语音（>60s）→ 分块转写后统一解析；重复误触 → 同一 `batch_id` 去重合并。

**评估集设计：** 40–60 条中文口语样本，覆盖时间表达 15 条（"明早""下周三""月底""三天后""周五前""今晚八点半"）、多任务 10 条、重复 8 条、无时间/想法 10 条、口误口水话 5 条、对抗样本 5 条（相对时间跨天、"大后天"、方言数字）。每条标注期望 JSON 与可接受变体。指标：① 标题语义准确率（人工 1–5 分）；② 时间字段准确率（日期/时刻分开算）；③ 拆分 precision/recall/F1；④ 误建率（不该建却建）；⑤ P95 端到端延迟。建议验收线（建议后续验证）：时间准确率 ≥85%，拆分 F1 ≥0.8，误建率 ≤2%。

## 7. 遗漏清单（只列真正影响体验或架构的）

- **数据安全与备份**：单文件 SQLite + 自动滚动备份（保留 7 份）+ 一键导出 JSON；本地无云 = 硬盘坏即全丢，必须有备份叙事。
- **应用关闭时的提醒可靠性**：退出后无进程则提醒失效。方案：开机自启 + 常驻托盘 + Windows 任务计划程序兜底；若用户显式退出，需明确告知"退出期间不会提醒"。
- **时区/夏令时**：存 UTC 时间戳 + 原时区偏移；跨时区旅行、系统时钟被修改时避免"任务跳天"；中国无 DST 但导出/跨平台要考虑。
- **通知疲劳**：默认只在任务到点提醒 + 每日一次摘要，不做逐条完成通知、不做连续催促；免打扰时段默认 22:00–08:00。
- **无障碍**：全键盘可操作、屏幕阅读器标签、对比度；语音捕捉对行动不便用户是核心价值，不能只有鼠标路径。
- **隐私**：音频默认**不留存**（转写完成即删，或可选本地保留 24h 供纠错）；日志脱敏；模型与数据全部本地。
- **模型下载/更新体验**：体积 100MB–1GB，需断点续传、失败重试、版本变更时旧 JSON 兼容；更新不自动进行（避免占用带宽）。
- **跨平台**：先 Windows，但数据格式、快捷键抽象、悬浮窗 API 需预留；macOS/Linux 的窗口置顶行为差异大。
- **命名与商标**：Clarify 可能已有同名产品/商标，需在第 1 周查证（建议后续验证）；备选名要同步查。
- **单实例与开机自启**：多开会导致数据竞争；需单实例锁 + 提醒服务独立于窗口。

## 8. 待用户拍板的开放问题

1. **「等待他人」是否做成状态？** 推荐：不做，做 `#等待` 标签（v1）。
2. **24 小时清除默认是软归档还是硬删？** 推荐：软归档 30 天，设置可改 7/30/永久。
3. **是否保留优先级？** 推荐：不保留数字优先级，只保留「置顶」（≤3 条）。
4. **悬浮窗创建入口？** 推荐：语音原地录制，文本跳主窗输入页。
5. **默认显示方式？** 推荐：「今日清单」5 条，首次运行可一键换。
6. **多任务默认拆还是合？** 推荐：按解析拆分，同批次可一键合并；低置信度合并。
7. **退出应用后是否仍提醒？** 推荐：开机自启 + 托盘常驻 + 任务计划兜底，并在设置里明示边界。
8. **v1 是否做多清单/项目层级？** 推荐：不做；只做「收件箱 + 今天 + 标签」，减少概念数量。
