## 0. 一句话定义

**Clarify 是一个无需部署服务器的极简 AI 待办软件：用一句话把脑子里的东西说进去，云端 AI 自动把它变成排好期的待办，你只需要看和点完成。**

- 输入：全局快捷键 → 说一句（或打一句）→ 不打断当前工作
- 处理：本机语音识别（推荐）→ 云端大模型解析（用户自己的 API Key）→ 结构化 JSON → 默认安排
- 输出：常驻悬浮窗只显示少数真正要做的事；完成 24h 后自动从视野消失
- 边界：无账号、**无需部署服务器**、无遥测；数据存本机；音频默认不出机（本机识别）；文本会发给用户配置的模型厂商

### 主张（Product Thesis）

1. **零决策捕捉**：捕捉路径上用户只做一个动作（说/写），其他都交给默认规则。
2. **清晰是规则不是感觉**：用一组可执行的"清晰规则"约束界面（见 §3.3）。
3. **AI 在前台隐身**：AI 不当聊天助手，只当"安静的记录员 + 排期员"；永远不要求你确认。
4. **数据在你手里**：数据存本机、无自建后端、无账号；云端调用透明、可换厂商、可关。
5. **客户端即产品**：没有服务器要运维，也就没有"服务挂了"和"月账单"（费用走用户自己的模型账户）。

### 明确不做（v1 范围外）

- 不做自建服务器/账号体系/云同步服务（这是本项目的核心约束）
- 不做协作/共享清单、团队项目；不做聊天式 AI 助手或 AI 自动执行操作
- 不做日历双向同步、不做 Kanban/复杂层级/自定义字段
- 不做多端实时同步（schema 预留，后续可做"文件快照同步"）

## 1. 关键洞察：把"零决策"拆成可实现的三条规则

"全程不让用户做第二项决策"是最大承诺，也是最容易翻车的点。拆成三条可验证的规则：

- **R1 创建零决策**：捕捉时永不弹确认框。AI 输出的默认值直接生效，但每个默认值都**可被一键修正**（提示："我按 *明天 09:00* 安排了，点此修改"）。
- **R2 组织零决策**：不要求用户建清单/项目/标签。默认"今天 / 以后 / 等待"三个视图；标签可选、可被语音识别（"#工作"）但不强制。
- **R3 清理零决策**：完成即从视线消失；24h 后自动软归档；30 天内可恢复。用户永远不需要做"要不要删"的决定。

> 核心张力：**解析不可能 100% 正确**。"零决策"不等于"零纠错"。解法是**不阻塞的纠错**：默认值可视化、行内单击可改、10 秒撤销、低置信度自动降级进收件箱、原文永远保留。这比"创建前弹确认"体验好一个数量级，也更符合理念。

### 1.1 延迟悖论与"乐观 UI"

云端 LLM 解析通常 0.5~3 秒，但网络抖动、排队或 Key 未配置时会更久；用户同样不该等。链路必须"**先接住，后变聪明**"：

1. 语音停止的瞬间，用已转写文本创建草稿卡（标题=原话，时间=无）→ **立即上屏/进悬浮窗**，给"接住了"的微动效。
2. 后台 ASR 出 final → 云端 LLM/规则解析 → **原地升级**该卡片（标题精炼、补时间、必要时拆成多条）。
3. 用一条可点击的轻提示告知结果（"已安排 · 明天 15:00 · 与张总开会"），**不弹窗、不阻塞**。
4. 任何一步失败 → 保留原文进收件箱，绝不丢输入。

这条设计决定产品"感觉快"，而不是"实际快"。

## 2. 用户与场景（MVP 目标人群）

- **首要用户**：25~40 岁知识工作者、Windows 笔记本、事情多且碎片化、用过滴答清单/Todoist 但坚持不下来（"整理成本 > 收益"）。
- **核心场景**：
  1. 开会/走路/写代码时想起一件事 → 快捷键说一句 → 3 秒内回到手上的事。
  2. 坐在电脑前，悬浮窗就是"今天的台面" → 一眼看到 3~5 件事 → 点掉一件 → 它消失。
  3. 晚上打开主窗口，看今天完成了什么、清收件箱里 AI 没把握的几条。
- **次要场景**：纯打字建待办、推迟一件事、到点提醒。

## 3. 核心对象模型（最小化）

### 3.1 一个实体：`tasks`

不要一开始做清单/项目/看板层级。v1 数据模型：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT (uuid) | |
| title | TEXT | 精炼后的标题 |
| notes | TEXT NULL | 备注 |
| status | TEXT | `inbox` / `active` / `done` / `archived` |
| due_kind | TEXT | `none` / `date`（全天）/ `datetime`（定时） |
| due_at | TEXT NULL | ISO8601 带时区，`2026-11-02T15:00:00+08:00` |
| remind_at | TEXT NULL | 提醒时间（可早于 due） |
| recurrence | TEXT NULL | RRULE 子集：`FREQ/INTERVAL/BYDAY/UNTIL` |
| tags | JSON | 可空数组；"等待他人"用 `#等待` 标签而非状态 |
| pinned | INTEGER | 0/1，置顶（≤3 条），v1 唯一的"优先级" |
| batch_id | TEXT NULL | 同一次语音捕捉生成的条目共用，用于合并/撤销 |
| source | TEXT | `voice` / `text` / `quick` |
| raw_text | TEXT NULL | 原始口述，唯一真相；AI 结果可重算 |
| parse_confidence | REAL | 0~1；<0.6 进收件箱并打 ✨ 标记 |
| parse_meta | JSON NULL | 假设说明、source_span、模型版本 |
| sort_order | REAL | 手动排序 |
| created_at / updated_at / completed_at / archived_at | TEXT | |
| archived_reason | TEXT NULL | `done` / `dismissed` / `purged` |
| device_id / schema_version | TEXT / INT | 为未来同步/迁移预留 |

**重复任务**：单独 `task_completions` 表（task_id, completed_at, due_at_snapshot）。"完成"不结束任务，而是写完成日志、把 `due_at` 推进到下一次；"已完成"页展示完成日志。这样"今天跑完 3 公里"有打卡记录，又不在台面留痕。

### 3.2 状态机（4 态）

```
                    ┌─────────────┐
  语音/文字/快捷添加 → │   inbox     │  （未安排/待整理：无日期或低置信度）
                    └──────┬──────┘
         AI 解析出日期 / 手动排期 │
                           ▼
   ┌───────────────┐   ┌──────────┐  点击完成   ┌──────┐  24h 后   ┌──────────┐
   │   archived    │◄──│  active  │───────────►│ done │─────────►│ archived │
   │ (30 天后可删)  │   └──────────┘            └──────┘          │ (可恢复)  │
   └───────────────┘        │  ▲                   │              └──────────┘
                            │  └───────────────────┘ 撤销（10s 内 / 已完成页恢复）
                            └─ 清空日期 → 回到 inbox
```

- **逾期不是状态**：`active` 且已过期的查询结果，避免额外流转。
- **删除**：软删（`archived_reason=dismissed` + 30 天回收站）。
- **v1 只需 4 态**；"等待他人"用 `#等待` 标签（多一个状态=多一次选择）。

### 3.3 清晰规则（Clarity Rules，写进验收标准）

1. 悬浮窗同时展示 **≤ 5 项**（超出折叠"+N 项"），分组 ≤ 2 组。
2. 完成项 **1 秒内**从悬浮窗消失；主窗口"已完成"默认展示 24h。
3. 无日期事项只进 **收件箱**，不占悬浮窗（除非用户选收件箱视图）。
4. 每项默认 **单行**：复选框 + 标题 + 弱化时间；详情 hover/展开。
5. 悬浮窗最多 **一个数字**，禁止红点、角标、优先级色块。
6. 空状态也是设计过的状态（"今天清空了 🎉 / 说一句试试"），不能空白。
7. "已完成"页明确显示"23h 后自动清除"，让清空可预期。

## 4. 关键链路（交互状态机）

### 4.1 捕捉链路（语音/文字二合一入口）

**入口**：一个热键（`Ctrl+Alt+Space`）唤出**迷你捕捉条**，默认自动开始听；同一条里可直接打字，`Enter` 发文字。用户不需要先选"语音还是文字"。

```
空闲 ──热键(<150ms)──► 捕捉条（波形 + 流式字幕）
                 ├─ Esc / 再按 ──────────► 取消（<300ms 内视为误触，不落库）
                 ├─ 静音 1.2s / 松开 / 60s 上限 ──► 停止录音
                 ▼
            立即创建草稿卡（status=inbox，title=当前转写文本）
                 ▼
            ASR final → 云端 LLM / 规则解析（后台 0.5~5s）
                 ▼
            原地升级/拆分任务 → 轻提示"已安排 · 明天 15:00 · 与张总开会" [撤销]
```

要点：
- **按住说话**（可切"按一下开始/再按结束"）；`Esc` 取消；按住不足 300ms 视为误触。
- **失败兜底**：ASR 失败 → "没听清，已保留文字，可编辑"；LLM 请求失败/超时（>5s）/非法 JSON/**未配置 Key** → 走**规则解析**（日期/时间/重复/分句词典）；仍失败 → 原文进收件箱，绝不丢、不弹框。
- **AI 未就绪的三种状态**：未配置 API Key（引导去设置）｜网络不通（"已保存，联网后可重新解析"）｜本机语音模型未下载（降级手写 + 给下载入口）。不要都报"出错了"。
- **多件事**："明天下午三点跟张总开会，顺便买牛奶" → 拆 2 条（due 明天 15:00 / 无 → 收件箱），汇总提示"创建了 2 项"；同 `batch_id` 可一键合并。
- **乐观 UI 的视觉语法**：草稿卡有细微"正在理解"流光，解析完成 150ms 变形——这是产品"AI 感"最关键的 2 秒。

### 4.2 完成链路

单击复选框 → 打勾 + 划线（150ms）→ 从悬浮窗淡出（300ms）→ toast："完成 · 今天已完成 3 项" [撤销 10s]。
- 撤销：toast / 主窗口"已完成"恢复。
- 重复任务：完成本次后静默推进下一次，toast 显示"下一次：周一 09:00"；右键可"结束重复"。

### 4.3 24h 清空链路

- 后台任务（每小时/启动时）扫描 `status=done AND completed_at < now-24h` → 设为 `archived`（软）：从悬浮窗、今日、全部等常规视图彻底消失。
- 主窗口"已完成"页默认展示 **24h 内**完成记录 + 倒计时；更早的进"归档/回收站"，**30 天内可一键恢复**（设置可改 7/30/永久/立即）。
- **不要硬删除**：24h 自动删除 = 一次误点永久丢数据，违反"信任"；"清晰"靠视图过滤，不靠物理删除。

### 4.4 提醒链路

- `remind_at` 到点 → Windows 原生通知（标题 + 完成/推迟按钮）→ 点击打开主窗口定位。
- 应用托盘常驻 + 开机自启；用 `tokio` 30s tick + 监听系统唤醒/登录事件后**对账式**扫描 `due_at <= now` 的未提醒项（避免睡眠期间漂移）。
- 完全退出时 v1 用"下次启动补发 + 托盘常驻"保证不丢；v2 再上 Windows 计划通知/任务计划程序。首次设置里明示边界。

### 4.5 悬浮窗编辑链路

主窗口 →「悬浮窗」页 → **左侧实时预览**（真实渲染同款组件）+ 右侧配置 → 即时生效（无保存按钮）→ 悬浮窗可用鼠标拖动、位置记忆，提供"恢复默认"。

## 5. 悬浮窗：显示方式规格

悬浮窗不是"小组件"，是 Clarify 的**消费界面**；主窗口是管理界面。v1 **只做 3 种**，做精再扩。

| # | 模式 | 内容 | 适用人群 | 默认尺寸 |
|---|---|---|---|---|
| 1 | **今日**（默认） | 逾期 + 今天共 ≤5 条，底部"＋/🎤" | 大多数人 | 320×220 |
| 2 | **下一条** | 只显示最该做的一条（逾期 > 今天定时 > 今天全天），大字号+大勾，下下条 40% 透明 | 极简/专注 | 260×90 |
| 3 | **收件箱** | 未安排 ≤5 条，可一键排"今天/明天" | 收集型用户 | 280×自适应 |
| 4 | 时间轴 | 今日剩余时间线 | 日程型 | v1.1 |
| 5 | 极简计数 | 圆点+数字（逾期/今日），hover 展开 | 极致极简 | 64×52 |
| 6 | 自定义清单 | 某个标签/筛选 | 项目型 | v1.1+ |

**窗口行为（全模式通用）**：
- 无边框、圆角、半透明毛玻璃（Win11 Mica/Acrylic，降级纯色）、默认置顶、跳过任务栏、不在 Alt+Tab、**不抢焦点**。
- 拖动 + 边缘吸附（<24px）+ 记忆位置（多显示器按 ID + 归一化坐标，拔插兜底主屏）；可选"锁定位置"。
- 透明度三档 100/90/75%（不提供无级滑杆，防调成看不清）；hover 临时 100%。
- **点击穿透**开关（"锁定显示"模式开启穿透，配合热键切换）；全屏应用/专注助手/游戏时自动隐藏（可关）。
- 不允许盖住任务栏和系统托盘区域（避免"永远最上层"的失控感）。

**条目操作**：单击复选框=完成（唯一主操作）；悬停出现"推迟/编辑/打开"；右键菜单（推迟到今天/明天/下周、设提醒、删除、打开主窗）；标题双击行内编辑。

**创建入口（⚠️ 折中建议）**：**语音原地 + 文本跳主窗**。悬浮窗常驻 `🎤` 按下即录，不切窗（"说一句"才是零决策）；`＋` 唤起主窗口输入页并聚焦（文本需要编辑空间，且可编辑解析结果）。不推荐在悬浮窗内做内联文本输入——空间小、易误触。

## 6. 主窗口：页面地图、导航与按钮

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：搜索 / 命令面板 Ctrl+K        [＋ 新建（说/写）]      │
├────────┬───────────────────────────────────────────────────┤
│ 侧边栏  │  内容区                                            │
│ 今日    │  ┌────────────────────────────┐   ┌───────────┐  │
│ 收件箱  │  │ 列表（分组：逾期/今天/以后）  │   │ 详情抽屉   │  │
│ 全部    │  │  ☐ 与张总开会   15:00      │   │ 标题/时间  │  │
│ 已完成  │  │  ☐ 买牛奶                 │   │ 重复/标签  │  │
│ 悬浮窗  │  │  ...                      │   │ 原文/假设  │  │
│ 设置    │  └────────────────────────────┘   └───────────┘  │
└────────┴───────────────────────────────────────────────────┘
```

- **今日**（默认）：日期 + 三段分组（逾期 / 今天 / 无日期折叠）+ 行内快捷添加 + 顶部"一句话创建"输入条（可语音）。
- **收件箱**：AI 没把握 / 无日期的事项；顶部批量条（安排今天/明天、删除）；每条带 ✨ 或低置信度标记。
- **全部**：时间分组 + 标签筛选 + Ctrl+F 页内过滤；只做列表，不做看板。
- **已完成**：24h 内完成记录 + 倒计时；恢复/永久删除；更早的在归档/回收站（30 天）。
- **悬浮窗**：实时预览 + 模式/行为配置（见 §5）。
- **设置**：
  - 通用：主题（浅/深/跟随）、开机启动、托盘行为、快捷键、语言、更新
  - 语音与 AI：麦克风、识别方式（本机 / 云端）、语音语言、**模型服务商 + API Key + 模型名 + 测试连接**、默认时间规则（"明天"=09:00 还是全天）、本机语音模型下载/卸载
  - 提醒：到点通知、免打扰时段（默认 22:00–08:00）、每日摘要
  - 数据：存储路径、导出（JSON/Markdown）、导入、备份、回收站、清空、隐私说明
  - 关于：版本、更新、开源许可证、第三方模型服务条款
- **首次运行（<90 秒）**：欢迎（"数据只在本机，AI 用你自己的账号"）→ 语音识别方式（本机/云端）→ 填 API Key（可跳过，跳过=规则模式）→ 快捷键教学（实际按一次才通过）→ 试说一句 → 悬浮窗出现并高亮 3 秒。
- **快捷键**：`Ctrl+Alt+Space` 捕捉、`Ctrl+Alt+W` 显示/隐藏悬浮窗、`Ctrl+Alt+O` 主窗、`Ctrl+K` 命令面板、`Ctrl+Z` 撤销最近创建、`Ctrl+,` 设置、列表内 `Enter` 详情 / `D` 推迟明天 / `Del` 删除 / `Esc` 关闭。

## 7. AI 契约（AI 部分唯一需要严格定义的接口）

### 7.1 输入

- `transcript`：ASR 最终文本
- `now`：当前本地时间 + 时区（相对时间解析必需）
- `user_prefs`：默认时间规则（"明天"=09:00 / 全天、"下周"从周几）、常用标签、清单
- 输出必须**严格 JSON**（用服务商的 JSON mode / function calling；没有则本地校验+重试）

### 7.1.5 调用方式（无服务器，BYOK）

- 客户端**直接 HTTPS 调用**服务商的 OpenAI-compatible 接口（chat/completions，可选 audio/transcriptions），不经过任何自建服务器。
- Key 存在 **Windows 凭据管理器（DPAPI 加密）**，不写明文配置、不打日志；设置页可"测试连接"、可删除/更换。
- 服务商"适配器 + 预设"：DeepSeek / 通义千问 / Kimi / 智谱 / SiliconFlow / OpenAI / 自定义 base URL；默认给国内可直连的预设。
- 请求超时 5s、失败重试 1 次（指数退避）；记录 token 用量（本地统计，可显示本月粗估费用）。
- 断网/无 Key：不阻塞创建，走规则解析 + 原文收件箱，提供"联网后重新解析"批量按钮。

### 7.2 输出 Schema（草案）

```json
{
  "version": "1.0",
  "batch_id": "cap_01J...",
  "language": "zh",
  "tasks": [
    {
      "title": "和张总开会",
      "notes": null,
      "due": { "kind": "datetime", "at": "2026-11-02T15:00:00+08:00" },
      "remind": { "kind": "before", "minutes": 10 },
      "recurrence": null,
      "tags": ["工作"],
      "pinned": false,
      "confidence": 0.93,
      "needs_review": false,
      "assumptions": ["未说明日期，默认明天", "未说明时长，默认 1 小时"],
      "source_span": "明天下午三点跟张总开会"
    },
    {
      "title": "买牛奶",
      "due": { "kind": "none", "at": null },
      "tags": ["家"],
      "confidence": 0.55,
      "needs_review": true,
      "assumptions": ["没有时间线索，放入收件箱"],
      "source_span": "顺便买牛奶"
    }
  ],
  "split_reason": "两件独立的事，用逗号连接"
}
```

**硬规则**：
- 没有时间线索就 `due.kind="none"`，**绝不编时间**；有疑问给低 confidence + `needs_review`（true 也不弹框，只加一枚灰点）。
- 多意图用逗号/连词/换行拆分，单次最多 5 条；拆不动就一条（宁少拆、勿乱拆）；用 `source_span` 校验覆盖率。
- 相对时间必须结合 `now` 与时区（"下周三/半小时后/月底/周五前"）。
- 非法 JSON/缺字段 → 重试 1 次 → 规则解析 → 原文任务；**幻觉日期 = 0 容忍**（用 assumptions 暴露依据）。

### 7.3 评估集（开发前就建）

- 40~100 条真实中文口语样本：时间表达 15、多任务 10、重复 8、无时间/想法 10、口误口水 5、对抗样本 5（跨天"今晚"、"大后天"、方言数字）。
- 指标：① 时间字段准确率（日期/时刻分开算）② 拆分 P/R/F1 ③ 标题保真度 ④ 误建率/幻觉率 ⑤ P95 端到端延迟。
- 验收线：**时间准确率 ≥90% 才可默认用 LLM**（否则走规则）、拆分 F1 ≥0.8、幻觉日期 0、误建率 ≤2%。
- 没有它就会一直"感觉还行"——这是最容易省掉、又最该先做的事。

## 8. 技术选型（v0.3 更正版）

> 结论：**Tauri 2 + React 前端 + Rust 原生层 + 云端 LLM API（用户 Key）+ 可选本机 ASR**。不部署任何服务器。

### 8.0 三种"无服务器"的含义（先对齐概念）

| 说法 | 含义 | 本项目 |
|---|---|---|
| 不部署服务器 | 不需要自己租/维护后端，客户端直连模型厂商 | ✅ 是 |
| 不用配置任何东西 | 连 API Key 都不填（应用内置作者 Key） | ❌ 做不到：Key 放客户端会被抓包盗用；内置 Key 等于作者付钱，需要代理服务器/计费/风控 |
| 完全离线 | 断网也能转写和解析 | ⚠️ 部分：本机 ASR 可离线转写；云端解析需要网络，断网走规则兜底 |

**结论**：v1 采用"**无服务器 + 用户自带 Key（BYOK）**"。如果以后面向不想配 Key 的普通用户，再考虑付费版 + 代理服务器（那是新形态，不是 v1）。

### 8.1 架构（单进程 + 可选本机 ASR）

```
┌──────────────── Clarify.exe（Tauri 2）────────────────┐
│ WebView2: 主窗口(index.html) + 悬浮窗(overlay.html)     │
│ Rust: db(rusqlite) / window / tray / hotkey / 通知 / 调度│
│       ├─ 音频: cpal 录音 → 可选本机 ASR(sherpa-onnx)    │
│       ├─ 解析: 规则引擎 + HTTP 客户端(OpenAI-compatible) │
│       └─ 凭据: Windows Credential Manager (DPAPI)       │
└───────────────────────────┬────────────────────────────┘
                            │ HTTPS 直连（无自建服务器）
                            ▼
              DeepSeek / OpenAI / 通义 / Kimi / 自定义 base URL
```

不再需要 2.6GB 本地 LLM 和独立侧车引擎（除非以后加"纯本地模式"作为可选项）。若选**本机 ASR**：首次下载 228MB 模型，sherpa-onnx（Rust FFI，内置 Silero VAD），音频不出本机；若选**云端 ASR**：服务商 audio API，零下载但音频会上传且按分钟计费。

### 8.2 技术选型表

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Tauri 2.12.5 | 小、省内存、插件全；Win11 悬浮窗组合行为仍需 spike |
| 前端 | React 19 + TS + Vite + Tailwind + shadcn/ui | 双窗口双入口 |
| 原生层 | Rust | DB/录音/快捷键/通知/HTTP/凭据 |
| ASR | **本机** sherpa-onnx 2.0.1 + SenseVoice-Small int8（228MB，可选）**/ 云端** ASR（可选） | 本机：免费、离线、音频不出机；中文好 |
| LLM | **云端 API（BYOK）**：OpenAI-compatible chat + JSON mode | 候选：DeepSeek、通义千问、Kimi、智谱、SiliconFlow、OpenAI；适配器抽象 |
| 数据 | rusqlite + refinery，SQLite WAL，每日备份 | 只存本机 |
| 密钥 | Windows Credential Manager（DPAPI） | 不写明文、不打日志 |
| 分发 | NSIS/MSI + 签名 | 同前 |

### 8.3 关键取舍与风险

1. **API Key 配置门槛（新的头号产品风险）**：非技术用户注册厂商、找 Key 会卡住。对策：设置向导分步图文（打开→登录→复制→粘贴→测试）、内置 3 个国内常用预设、Key 只填一次、支持"先跳过（规则模式）后补"。若只给自己用，则不是问题。
2. **网络依赖**：断网时解析降级为规则（日期/时间/重复词典覆盖 70~80% 常见句式），创建永不失败；可"联网后重新解析"批量补。
3. **隐私**：文本必然离开本机（解析）；音频是否离开取决于识别方式。默认推荐**本机识别**（音频不出机），设置里写清楚；分发需隐私政策。
4. **费用与限额**：单次解析约几百 token，按便宜国产模型估算每天几十次约几毛钱以内（**粗略量级，需按厂商现价核实**）；做"本月用量"本地统计与提醒，不做强制计费。
5. **厂商差异**：JSON mode / function calling / 限流 / 超时各不同；统一适配器 + 每个预设给推荐模型与超时；不可用时可切换。
6. **厂商网络可达性**：国内用户默认预设国内厂商（DeepSeek/通义/Kimi/智谱/SiliconFlow）；OpenAI 放"自定义"里。
7. **Tauri 悬浮窗组合行为**：与 v0.2 相同，第 1 周 spike。

### 8.4 性能预算（验收标准）

| 指标 | 目标 |
|---|---|
| 热键 → 捕捉条出现 / 开始录音 | < 150 ms |
| 本机 ASR 10s 语音端到端 | < 2 s（P95） |
| 停止 → 草稿卡出现（乐观 UI） | < 300 ms（不等 AI） |
| 云端解析（单条语音） | < 3 s（P95，国内厂商网络正常） |
| JSON 合法率 | ≥ 99%（JSON mode/重试后） |
| 抽取字段准确率 | ≥ 90%（评估集），否则走规则 |
| 空闲常驻内存 | < 250 MB |
| 冷启动到悬浮窗可见 | < 2.5 s |
| 安装包（不含可选本机模型） | < 80 MB |

### 8.5 技术尖峰（Spike A，2~3 天）

1. Tauri 悬浮窗组合行为（透明/置顶/穿透/拖拽/多屏/全屏隐藏）。
2. 云端解析：用 50 条真实中文口语 + 真实 API，测 P50/P95 延迟、JSON 合法率、抽取准确率。
3. 本机 ASR：SenseVoice 真实录音上的中文准确率/延迟（决定默认识别方式）。
4. Key 配置 + 测试连接 + 断网降级 + 网络错误重试（端到端走一遍）。
5. 可选：云端 ASR 对比（识别质量/成本）。

任一项不达标 → 调整（壳换 Electron / 识别换云端 / 解析换厂商），不推倒产品设计。

## 9. 非功能需求

- **隐私**：默认本机识别、音频不出机；文本会发送到用户配置的模型厂商（设置页明示）；Key 加密存储；无遥测；数据目录可迁移。
- **网络**：断网不影响创建与浏览；AI 解析降级为规则 + "待重新解析"队列；所有网络失败可重试、可离线恢复。
- **可靠性**：SQLite WAL + 每日快照（7 天）+ `VACUUM INTO`；崩溃恢复；录音中崩溃保留临时文本。
- **可维护**：解析器/服务商/模型可替换（适配器接口隔离）；migration 版本化；解析评估集 + Rust 单测。
- **分发**：NSIS/MSI；代码签名；v1 内测可先不签名但需提示。
- **可访问性**：全键盘、快捷键可改、高对比度、字号缩放（次级优先级）。

## 11. ⚠️ 需要你拍板的问题（按重要性排序）

1. **AI 服务形态**：A) **本机语音识别 + 云端 LLM 解析**（推荐：音频不出机、免费离线转写、云端理解好）；B) 全部云端（零下载、识别更稳，但音频上传 + 按量付费）；C) 全部本机（完全离线，但下载大、CPU 慢、体验重）。
2. **API Key**：你是否接受第一次设置时填一次 API Key？（不想填的话，就需要"付费版内置 Key + 代理服务器"，成本由你承担，与"不部署服务器"冲突。）
3. **"自动解析安排"的边界**：A 只解析结构化字段（推荐）/ B 解析 + 自动排进今天时间表 / C + AI 每日规划。
4. **断网行为**：A 可降级（规则解析 + 收件箱，联网后重新解析）——推荐；B 必须完全可用（那要本机 LLM，体验重）。
5. **平台/分发**：A 只 Windows 自用（最快）/ B Windows + macOS 发布 / C 商业化/上架。
6. **技术栈与你的经验**：Tauri/Rust 还是 Electron/TS？（你熟哪个很关键。）
7. **捕捉入口**：A 语音原地 + 文本跳主窗（推荐）/ B 悬浮窗内联文本 / C 全部跳主窗。
8. **清单/标签**：A v1 完全不分类（推荐）/ B 只做标签 / C 自定义清单。
9. **提醒**：v1 必须做到点通知 + 睡眠补发，还是先只做当日清单？
10. **视觉风格**：A 纸张感极简（推荐）/ B 信息密度高的效率工具。

## 12. 你还没考虑、但会影响成败的事（遗漏清单）

1. **数据丢失 = 产品死亡**：本地无云端兜底，必须自动备份 + 导出 + 回收站；"24h 自动删除"必须软删。
2. **首次体验 3 分钟**：现在只剩"填 Key + 可选 228MB 本机模型下载"；仍要分步向导、可跳过、国内厂商预设，否则非技术用户会卡在注册 API。
3. **AI 评估集**：不建 40~100 条真实中文语料，AI 质量永远靠感觉；这是最容易省、又最该先做的事。
4. **提醒可靠性**：应用关闭/睡眠/关机期间无法触发；开机自启 + 托盘常驻 + 补发 + 明示边界。
5. **AI 未就绪的三种状态**：未配置 Key / 网络不通 / 本机模型未下载——分别有引导与降级路径，不能都报"出错了"。
6. **API Key 安全与费用**：Key 加密存储、不写日志；用户可能忘了自己开了多少用量——本地统计 + 余额提醒。
7. **许可证与条款**：本机 ASR 权重（SenseVoice）非 OSI；云端 API 受厂商条款约束；若分发需隐私政策与用户协议。
8. **Tauri 悬浮窗组合行为风险**：第 1 周 spike 决定壳选型；失败切 Electron。
9. **命名/商标**：Clarify 已被多家 CRM/软件使用，公开分发前查证；先用内部代号也可。
10. **多显示器/高 DPI/虚拟桌面/全屏应用**：悬浮窗行为要逐个测，否则显廉价；v1 可先保证主屏。
11. **重复任务 × 24h 清空 × 撤销**：状态机最易出 bug，先写测试用例。
12. **解析歧义产品化**：无日期 ≠ 忘了；"下周"从周几算；跨天边说"今晚"；默认规则要可设置。
13. **隐私承诺要可验证**：本机识别时音频不出机、无遥测要写清楚，代码里真的做到。
14. **Windows 签名/SmartScreen**：不签名影响信任；证书约 ¥1–3k/年，提前决定。
15. **迁移**：用户已有滴答/Todoist 数据怎么办？v1 可不做但要说明。
16. **同步**：v1 不做，schema 预留 `updated_at/device_id`，未来文件快照同步（iCloud/OneDrive）不推倒重来。
17. **费用失控感**：如果一次语音输入被解析成 5 条，token 也不多；真正的费用风险是"AI 每天自动生成建议"这类后台调用——v1 不做后台自动调用。
18. **崩溃恢复**：录音中崩溃不能丢输入（临时文件）。
19. **度量**：从第一天记录本地指标（捕捉耗时、解析失败率、重试率——只存本地），否则无法迭代。
20. **重复/误触**：连按热键、重复口述同一件事 → 同 batch_id 去重；同标题 10 分钟内提示合并，不自动合并。
21. **空状态与引导**：新用户第一次看到"说一句试试"比空白列表重要。
22. **可测试的验收标准**：每个里程碑定义"能做什么"，而不是"写完了"。
