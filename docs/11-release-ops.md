## 1. 分发物与安装包

### 1.1 发布物清单（每个版本）

| 文件 | 内容 | 是否必需 | 生成方式 |
|---|---|---|---|
| `Clarify_<version>_x64-setup.exe` | NSIS x64 安装包（per-user，无管理员权限） | 是 | `pnpm tauri build`（release） |
| `latest.json` | 自动更新清单（含 Windows 平台签名与下载 URL） | 是（启用更新时） | 脚本从构建产物生成并校验（§2.2） |
| `*.sig` | 更新签名（Tauri updater，minisign 格式） | 是（启用更新时） | `tauri signer sign`（私钥离线保管） |
| `SHA256SUMS.txt` | 安装包 SHA256（防篡改/传输校验） | 是 | `certutil -hashfile` 或脚本 |
| Release Notes（中文） | 本版变化、已知问题、数据影响提示、安装说明 | 是 | 人工编写（模板 §13.2） |
| 回滚包链接 | 上一版本安装包（GitHub Release 保留） | 是（内测） | 不删除上一版 Release asset |
| 调试符号（可选，私有） | `.pdb`，仅本地/私有存储用于排障 | 否 | 构建归档（不上传公开 Release） |

**纪律**：仓库与安装包内**不得**包含真实 API Key、激活码、签名私钥、用户数据。CI 构建使用仓库 Secret/本地环境变量（`08-engineering.md`）。

### 1.2 构建与可复现性

1. 版本号唯一来源：`package.json` / `tauri.conf.json` / Cargo 版本在发布脚本中校验一致；安装包与 `latest.json` 版本必须相同。
2. 记录构建输入：commit SHA、Node/pnpm/Rust/MSVC 版本、lockfile 哈希、WebView2 bootstrapper 版本；写入 Release Notes 或构建日志归档。
3. 干净构建：CI 或干净目录执行 `pnpm install --frozen-lockfile && pnpm tauri build`；不得在开发机上"手工拼装"发布包后直接上传。
4. 构建后校验：安装包大小（目标 <80MB，PERF-08）、文件版本信息、图标/签名（若有）、启动冒烟（§11）。
5. 打包配置要点：NSIS 目标、`webviewInstallMode: embedBootstrapper`（避免安装时联网，+~1.8MB）、per-user 安装（不触发 UAC）、开始菜单/桌面快捷方式可选、卸载保留数据策略（§1.4）。

### 1.3 安装、升级、卸载行为

| 行为 | 规格 | 备注 |
|---|---|---|
| 安装位置 | 用户级目录（如 `%LOCALAPPDATA%\Programs\Clarify`），无需管理员权限 | 内测简化；避免 UAC |
| 安装向导 | 极简：许可（内测提示）→ 安装路径（默认）→ 完成；不提供"首次引导"（产品决策） | 安装完成启动即主页面 |
| WebView2 | 内置 bootstrapper；已安装则跳过；安装失败给出可读错误与手动安装链接 | Win10 老机器兜底 |
| 数据目录 | 与安装目录分离（`%APPDATA%\Clarify` 或 `%LOCALAPPDATA%\Clarify`，最终位置见产品决策 §10-1） | 卸载默认保留（防误删） |
| 升级 | 覆盖安装保留数据与设置；schema 前向迁移（禁止降级）；升级前自检（§7.4） | 与自动更新共用 |
| 卸载 | 可选"保留本地数据"（默认）/"同时删除本地数据"；卸载完成提示数据位置 | 无备份/导出，默认保留是安全选择；需明确文案 |

### 1.4 代码签名

| 阶段 | 签名 | 后果/要求 |
|---|---|---|
| 内测（v1） | **暂不签名**（ADR-0007 允许） | 用户会看到 SmartScreen"未知发布者"；安装指引必须包含 SHA256 校验与来源说明；Release Notes 明示未签名 |
| 公开分发 | **必须签名** | OV/EV 代码签名证书或云签名（HSM）；证书成本约 ¥1–3k/年（**待核实**，以 CA 报价为准）；签名含时间戳；`signtool verify /pa` 通过 |

签名纪律：私钥/证书放 HSM 或密码管理器，绝不进仓库；签名在受控环境执行；每次发布记录证书指纹与签名时间；如证书泄露按 §9 RB-03 处理。

### 1.5 兼容性基线

- 系统：Windows 11 x64 为主（23H2/24H2）；Windows 10 22H2 尽力支持（WebView2 可能需安装）。
- 不做：x86、ARM64（v1 不承诺）、macOS（远期）。
- 依赖：WebView2 Evergreen Runtime（安装包内置 bootstrapper）；系统字体（不随包分发，见 ADR-0008）；无其他运行库依赖。
- 显示：100%/150% DPI、单/双显示器；多屏位置记忆兜底主屏。

## 2. 自动更新

### 2.1 方案（ADR-0007）

- **GitHub Releases + 静态 `latest.json` + Tauri updater**；不自建更新服务器、不做灰度服务端。
- 客户端内置更新公钥；下载后校验签名，失败拒绝安装；HTTPS only。
- 更新检查：启动后延迟异步检查（不阻塞首屏）+ 设置中手动"检查更新"；可"跳过此版本"。
- 下载：后台静默下载（可配置）；安装前提示"重启以应用更新"，不强制重启。
- 禁止降级：`allowDowngrades = false`；旧客户端不感知新版本限制（通过 `minimum_version` 或在客户端业务层拦截）。
- 内测期建议：自动检查 + **手动确认安装**；先在内测小范围验证更新链路，再默认自动下载。

### 2.2 `latest.json` 模板（占位，禁止填真实值）

```json
{
  "version": "0.9.0",
  "notes": "内测版：新增 A/B 模板、悬浮窗、24h 清理；无备份/导出。",
  "pub_date": "2027-02-15T08:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<BASE64_MINISIGN_SIGNATURE>",
      "url": "https://github.com/<ORG>/<REPO>/releases/download/v0.9.0/Clarify_0.9.0_x64-setup.exe"
    }
  }
}
```

- `signature` 必须来自本版安装包的更新签名文件；`url` 必须可匿名下载、大小写一致。
- 更新 `latest.json` 的时间点：安装包与签名上传成功且冒烟通过后，**最后一步**替换；避免"清单指向不存在的包"。
- 生成/校验脚本应固化：版本一致性检查、签名校验、JSON 语法、URL HEAD 200、SHA256 对比。

### 2.3 发布与更新流程（SOP）

1. 冻结代码（tag `v<version>`）→ 构建 → 冒烟（§11）→ 生成签名/SHA256/latest.json。
2. 先建 GitHub **Pre-release** 上传产物（内测可先用 pre-release 验证）。
3. 内测验证：用上一版本安装包 → 更新到本版本；验证数据保留、签名校验、安装/重启。
4. 验证通过后：发布为正式 Release（或保持内测 pre-release）；将 `latest.json` 上传到 update endpoint 指向的位置（仓库 latest release 的固定下载 URL 需指向 stable；内测另设测试 endpoint 或手动安装）。
5. 公告：内测群 + Release Notes（含数据影响、已知问题、回滚方式）。
6. 发布后 24h 观察：新版本崩溃反馈、更新失败率、AI 调用异常。

### 2.4 更新失败与回滚

| 场景 | 处理 |
|---|---|
| 用户更新失败（下载失败/签名失败） | 客户端保留旧版本运行；提示手动下载安装包；不破坏数据 |
| 新版本启动崩溃 | 回滚：将 `latest.json` 指回上一版（或撤回 Release）→ 引导用户重新安装上一版（客户端不支持自动降级）；发布修复版 ≤24h |
| 数据迁移失败 | 回滚不解决数据问题（无备份）；按 §7.4 预先自检 + 迁移仅前向 + 失败回滚事务；见 RB-05 |
| GitHub 不可达 | 手动下载页/对象存储镜像（内测群直接发安装包 + SHA256）；更新检查失败不打扰用户 |
| 坏包已扩散 | 立即撤回 Release/替换 `latest.json` + 群公告 + 修复版；记录到故障复盘 |

**纪律**：任何情况下**不删除**上一版本 Release 产物；回滚包至少保留最近 3 个版本。更新私钥丢失/泄露 → 必须更换内置公钥并发版（旧客户端无法自动更新到新公钥版本，需手动重装；因此私钥必须离线多副本保管）。

## 3. 版本策略

### 3.1 语义化版本（SemVer 2.0.0）

| 位 | 递增条件 | 示例 |
|---|---|---|
| MAJOR | 不兼容的数据/schema/契约变更（升级不可逆、需用户干预） | `1.0.0` 后 `2.0.0` |
| MINOR | 向后兼容的新功能 | 新增模板/视图能力 |
| PATCH | 向后兼容的缺陷修复 | 崩溃修复、文案 |

预发布：`0.9.0-beta.1` → `0.9.0-beta.2` → `0.9.0`。内测包使用 `0.x` 预发布，稳定自用/内测版从 `1.0.0` 起。

### 3.2 内部版本映射（计划）

| 里程碑 | 版本示例 | 内容 |
|---|---|---|
| M1 出口 | `0.1.0` | 后端/底层可验收（内部构建） |
| M2 出口 | `0.2.0` | 主窗/悬浮窗 UI 可验收（内部构建） |

| v1.0 内测/自用 | `1.0.0` | 内测复盘后发布 |

### 3.3 独立版本号（必须分别记录）

| 版本 | 含义 | 管理 |
|---|---|---|
| 应用版本 | 安装包/更新 | 本节 |
| DB schema 版本 | 迁移序号（`schema_migrations`） | `05-contracts/storage-schema.md`，**只前向** |

### 3.4 变更日志（CHANGELOG / Release Notes）规则

- 用户语言、可读、不写内部术语；必须包含：新增/变化/修复/已知问题。
- **数据与隐私影响必须显式写**：如"本版会清理 24h 前已完成项""本版修改了 AI 请求内容范围""内测升级可能有数据迁移，本软件无备份与导出"。
- 安全修复合并后不晚于下次发版披露；内测阶段可直接在群内说明。
- 不做"每日构建"发布；内测期按需发补丁版（`0.9.x`）。

## 4. 隐私政策要点（内测版，公开前需法律评估扩写）

> 原则：数据本机、最小化、可解释、可删除；无账号/无遥测/无云同步/无备份导出（产品决策 §7/§9）。
> 实现要求：隐私说明在**无首启引导**前提下必须可达（位置待定，产品决策 §10-17；M4-06 决定并落地，候选：设置-关于/隐私、安装包内 README、内测群公告）。

### 4.1 数据处理清单（隐私政策核心表）

| 数据 | 是否离开本机 | 接收方 | 用途 | 保留期 | 用户控制 |
|---|---|---|---|---|---|
| 事件内容（标题/时间/重复/计数/完成日志） | **否**（仅本机 SQLite） | — | 产品功能 | 未完成：直到用户删除；已完成（单次/无时间）：24h 后物理删除；周期完成日志：各自 24h 后删除（系列行保留）；计数：周期边界清零，无 24h 删除 | 编辑/删除（分形态，不可恢复） |
| 设置/偏好 | 否 | — | 产品功能 | 直到卸载/删除数据 | 修改/卸载删除 |
| 录音音频 | **是**（仅传输瞬时） | ASR 厂商（官方网关转发的阿里云百炼；或 BYOK 用户自选厂商） | 语音转文字 | **不落盘**（客户端/网关均不保存；转写完成即丢弃） | 不用语音即不产生 |
| 转写文本 | **是** | DeepSeek（官方网关转发；或 BYOK 用户自选） | 解析为结构化事件 | 网关不记录正文；厂商侧按其条款 | 规则模式可完全关闭云解析 |
| 激活码 / 设备标识 | 是 | 官方网关（阿里云 FC） | 鉴权、配额、防滥用 | 网关侧用量记录 ≤30 天（建议）；客户端保留 | 换激活码/不用官方服务 |
| 调用用量元数据（延迟/状态/字数/秒数） | 是 | 官方网关/云平台 | 配额、预算、排障 | ≤30 天（建议） | 不适用（不含正文） |
| 本地运行日志 | 否 | — | 排障 | ≤7 天（建议），不含正文/音频/Key | 可关闭/手动清理 |
| 崩溃转储 | 否（不上传） | — | 排障（用户自愿提供） | 本地 ≤7 天（建议） | 用户决定是否提供 |
| 遥测/使用统计 | **不收集** | — | — | — | — |

### 4.2 必须写明的要点

1. **AI 传输边界**：语音会发往 ASR 厂商、转写文本会发往 DeepSeek（官方网关模式经作者轻量网关转发；BYOK 模式直连用户配置的厂商）。BYOK 若选择境外厂商，数据可能出境，由用户自行判断（隐私政策需提示）。
2. **本机数据**：数据只存本机 SQLite；无账号、无云同步、无遥测；**不提供备份与导出**；换机/重装/删库/磁盘损坏无法找回；数据丢失后果需用户知悉（与 `06-adr/0004` 一致）。
3. **删除机制**：已完成项 24 小时后**物理删除**；周期型完成只删"本次"、系列保留；详情抽屉删除**不可恢复**（分形态，见 §7.3）；卸载可勾选同时删除本地数据。删除不可撤销。
4. **安全措施**：BYOK Key 存 Windows 凭据管理器（DPAPI）；官方厂商 Key 只在网关环境变量；日志脱敏；网关不保存音频/正文。当前**数据库未加密**（v1 默认，待决策 §10-1；公开前应评估 SQLCipher/DPAPI 加密）。
5. **用户权利**：访问/更正（直接在应用内查看编辑）、删除（删除/卸载）、撤回 AI 处理（切换规则模式/停用官方服务）；**无导出**导致"数据可携带"受限，公开分发前必须评估法律冲突（§10 标记）。
6. **未成年人**：v1 不面向未成年人设计；内测限成年人（用户名单确认）。
7. **敏感个人信息提示**：录音中可能包含声纹等生物识别信息，属于敏感个人信息；内测版需在告知中**单独提示并取得同意**（内测知情同意，§12.3）；公开版需单独同意流程与 PIPIA 评估。
8. **政策更新**：更新通过 Release Notes + 设置页版本化文本告知；不弹首启引导；重大变更需用户重新确认（内测群/应用内提示）。
9. **联系方式/投诉**：占位邮箱 `<PRIVACY_CONTACT>`（发布前填写真实联系方式，不写进代码仓库明文可用占位）。

## 7. 数据保留与删除策略

> 与 `06-adr/0004`（数据与删除）一致；实现细节见 `05-contracts/storage-schema.md`。**核心承诺：本机、最小化、删除不可恢复、无备份导出。**

### 7.1 保留与删除矩阵

| 数据 | 存储位置 | 保留期 | 删除方式 | 可恢复？ |
|---|---|---|---|---|
| 未完成事件（单次/无时间/周期当前 occurrence/计数） | 本机 SQLite | 直到用户删除 | 详情抽屉删除（分形态，见 §7.3；不可恢复） | 否 |
| 已完成事件（单次/无时间型） | 本机 SQLite | 完成后 **24h**（`completed_at+24h`） | 清理作业**物理删除整行** | 24h 内可恢复；之后**否** |
| 周期型事件行（系列） | 本机 SQLite | 直到用户删除/结束系列 | **不会**因完成或 24h 清理删除；删除本次=推进下一次 | 否 |
| 周期型完成日志（`event_completions`） | 本机 SQLite | 每条日志完成后 **24h** | 清理作业**物理删除日志**；系列保留 | 24h 内可恢复（仅最新一条）；之后**否** |
| 计数进度（`count_progress`/`count_period_key`） | 本机 SQLite | 当前周期；跨边界清零 | 周期边界重置；删除事件时随行删除；**无 24h 删除** | 否 |
| 设置/偏好 | 本机 SQLite | 直到卸载/删除数据 | 应用内修改；卸载勾选删除 | 否 |
| 本地日志 | 本机文件 | ≤7 天（建议） | 自动滚动删除/手动清理 | 否 |
| 崩溃转储（若产生） | 本机文件 | ≤7 天（建议），不上传 | 手动删除/自动清理 | 否 |
| 音频 | 内存/临时缓冲 | **不持久化**；转写后即丢弃 | 进程退出/失败清理 | 否 |
| 网关用量元数据 | 阿里云 FC 日志/OSS | ≤30 天（建议） | 定期清理/生命周期规则 | 否 |
| 激活码/设备绑定 | 网关侧 | 内测期 + 吊销后 30 天（建议） | 吊销/删除 | 否 |
| 备份/导出 | **不存在** | — | — | — |
| 回收站/软删除 | **不存在** | — | — | — |

### 7.2 "物理删除"的实现与验证要求

1. 24h 清理与用户删除必须**真实 DELETE 行**（不存在软删除标记/回收站表）；按形态级联清理关联记录：
   - 单次/无时间型已完成且 ≥24h → DELETE 事件行；
   - 周期型完成日志 ≥24h → DELETE 日志行；**事件行（系列）永不因完成/清理删除**；
   - 计数型无 24h 删除，只在周期边界重置；
   - 用户删除周期型 = 只删"本次"（推进下一次，不写日志）；删除单次/无时间/计数型 = DELETE 整行并级联删除完成日志。
2. 隐私层面（公开分发前必须满足，内测记为 P1）：
   - `PRAGMA journal_mode=WAL` 下，删除行可能残留在 WAL/空闲页；发布要求至少执行 `wal_checkpoint(TRUNCATE)`；公开前评估 `PRAGMA secure_delete=ON`/定期 `VACUUM`；
   - 验收查询：`SELECT COUNT(*) FROM events WHERE id IN (...)` = 0，且用文件级扫描验证敏感标题不残留（T-RS-DEL-008）。
3. 卸载删除数据：删除数据目录（`%APPDATA%\Clarify` 或最终定稿路径）；确认无残留。
4. 删除不可恢复：无备份、无导出、无回收站（产品决策），客服口径统一"无法找回"，不得私下承诺恢复。

### 7.3 数据删除的用户路径

| 场景 | 用户操作 | 结果 |
|---|---|---|
| 删除单次/无时间/计数型 | 详情抽屉删除 | 立即永久删除整行（不可恢复） |
| 删除周期型 | 详情抽屉删除 | **只删"本次"**：推进到下一次，系列保留；被删这次不可恢复 |
| 结束重复系列 | 详情把"重复"改为无 → 再删除 | 变为单次后删除整行；仅清时间保留重复会被拒绝 |
| 已完成项 | 无删除入口 | 24h 内可恢复；之后自动物理删除（不可恢复） |
| 已完成项清理 | 无需操作 | 完成 24h 后自动物理删除（周期日志各自 24h；计数无此项） |
| 清空全部本机数据 | 卸载时勾选"删除本地数据" | 数据目录删除 |
| 退出官方 AI 服务 | 设置切换规则模式 / 删除激活码 | 后续不走官方网关；本机数据保留 |
| AI 请求撤回 | 切换规则模式 | 后续捕捉不再上传音频/文本 |

### 7.4 升级与迁移的数据安全（无备份前提）

- DB 迁移**只前向**、事务内执行；迁移前做只读校验与 dry-run（在副本上演练，不修改唯一生产库）。
- **是否允许迁移前生成内部临时快照（成功后立即删除）尚需 Lead 决策**（与"不做备份"承诺的边界）：默认方案 = 迁移前仅做完整性校验 + 失败自动回滚事务；若用户数据损坏风险高再评估临时快照（必须在隐私政策与实现中说明"临时、自动删除"）。
- 迁移失败：客户端明确提示、保留旧库（不覆盖）、给出恢复路径（重装旧版包），并上报开发排障。
- 禁止在升级流程中自动"清理旧数据"以外的破坏性操作。

## 8. 官方服务（网关）运营

> 部署细节见 `docs/ops/official-ai-gateway-setup.md`、契约见 `05-contracts/gateway-api.md`、ADR-0001/0002/0006。

### 8.1 部署与配置

- 形态：阿里云函数计算 FC（Node 20）+ 默认 HTTPS 域名（内测不买域名、不备案）+ OSS/日志记录用量（D17）。
- 环境变量（占位，真实值只在云平台配置，**不进仓库**）：
  - `DEEPSEEK_API_KEY=<SECRET>`
  - `ASR_PROVIDER` / `ASR_CREDENTIALS=<SECRET>`
  - `ACTIVATION_CODES=<HASHED_LIST_OR_STORE>`
  - `DAILY_QUOTA=200`、`MONTHLY_BUDGET_CNY=200`、`BUDGET_ALERT_RATIO=0.8`
  - `LOG_LEVEL=info`（禁止 debug 打印正文）
- 激活码：随机生成（≥16 字符分组），网关只存哈希/标签/设备绑定/状态；发放记录表（编号、领取人、日期、状态）用私有表格维护，禁止明文进群公告以外的公开渠道。
- 预算：阿里云费用中心设置月度预算 ¥200，80%/100% 告警；达 100% 时网关拒绝 AI 调用并返回可识别错误（客户端切规则模式）。
- Key 轮换：每 6 个月或疑似泄露时轮换；流程 = 新 Key 生效 → 观察 24h → 旧 Key 停用；记录轮换日期。

### 8.2 监控与例行动作

| 频率 | 动作 | 产出 |
|---|---|---|
| 每日（内测期） | 查看 FC 错误率/延迟（P95）、调用量、异常 401/429 峰值 | 异常即按 §9 处理 |
| 每周 | 用量与成本核对（次数/秒数/token × 单价）、预算进度 | 周报（内测群摘要） |
| 每月 | 预算复核、激活码/设备清单核对、Key 有效期、依赖漏洞巡检 | 月度运营记录 |
| 发版前 | 网关 `/v1/health`、契约测试、额度/预算演练（小额） | 发版检查项 |

异常信号：单设备日调用接近/超过 200；单 IP 短时大量请求；401/403 激增；成本单日 > 预算/30 的 3 倍；上游错误率 >5%。

### 8.3 应急开关

1. **停用官方网关**：将客户端默认模式降级为规则（服务端返回 503 + 客户端自动规则）；群公告。
2. **吊销激活码**：按设备/批次吊销；客户端下次请求收到 401 → 提示切换 BYOK/规则。
3. **停止厂商 Key**：云平台停用环境变量 → 网关返回可识别错误。
4. **限流**：降低 `DAILY_QUOTA` / 增加网关节流（按契约留出客户端降级）。

## 12. 内测运营与支持

### 12.1 名单与额度

- 5–10 人（设计容量 ≤20）；内测前收集：Windows 版本、是否愿意接受数据风险、联系方式；
- 每人分配独立激活码（可吊销、可设额度）；预算按 charter D12：每设备每日 200 次、月预算 ¥200 告警；
- 名单维护：编号、昵称、设备、激活码哈希/尾号、加入日期、状态（活跃/退出/吊销）。**不记录明文激活码**（除一次性发放渠道）。

### 12.2 安装与升级支持

- 提供 `Clarify_<version>_x64-setup.exe` + `SHA256SUMS.txt` + 图文安装指引；
- 说明未签名与 SmartScreen 处理（"更多信息 → 仍要运行"），并要求先核对 SHA256；
- 说明无备份/导出、删除不可恢复、24h 物理删除、音频/文本发往第三方；
- 升级方式：应用内更新（若开启）或覆盖安装；禁止降级；内测升级前提醒"数据可能受迁移影响"。

### 12.3 内测知情同意（必须）

向每位内测者单独确认（群公告 + 接龙/表单留痕）：
1. 已知晓软件为内测版，可能不稳定/停机/数据受影响；
2. 已知晓**无数据备份与导出**，换机/重装/损坏/误删无法找回；
3. 已知晓已完成项 24h 后**物理删除**、删除**不可恢复**；
4. 已知晓录音会发往 ASR 厂商、转写文本会发往 DeepSeek（或 BYOK 自选厂商）；含声纹的敏感信息处理；
5. 同意不将内测包转给他人（激活码绑定设备、可吊销）。

### 12.4 反馈渠道与分诊

- 渠道：内测群 + 反馈表（字段：版本/系统/网络/AI 模式/步骤/期望/实际/截图/日志是否愿意提供）；
- 分诊：每日 30 分钟；按 `07-test-strategy.md` §11 分级；P0 当日响应；
- 周报：本周修复、已知问题、下周计划、风险提示；
- 退出：用户可随时退出；退出后删除其激活码/设备绑定（不保留可识别个人信息）。

### 13.5 数据删除验证 SQL（示意，字段以 03/05 契约为准）

```sql
-- 24h 清理后应无记录（单次/无时间型已完成行）
SELECT COUNT(*) FROM events WHERE completed_at IS NOT NULL
  AND repeat_freq IS NULL AND count_target IS NULL
  AND completed_at <= datetime('now', '-24 hours');
-- 周期完成日志清理后应无记录（事件行仍在）
SELECT COUNT(*) FROM event_completions
  WHERE completed_at <= datetime('now', '-24 hours');
-- 用户删除后应无记录与孤儿
SELECT COUNT(*) FROM events WHERE id = '<deleted_id>';
SELECT COUNT(*) FROM event_completions WHERE event_id = '<deleted_id>';
-- 计数型不得被 24h 清理删除（只应存在周期键重置）
SELECT COUNT(*) FROM events WHERE count_target IS NOT NULL AND count_progress > 0;
```
