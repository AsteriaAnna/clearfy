> 一句话：**一件事 = 一个动作标题 + 若干可选字段（时间 / 重复 / 计数目标）；不存类型，形态由字段组合推导；只有未完成与已完成两种状态（用 `completed_at` 或完成日志表达）；已完成在主窗底部折叠、24 小时内可恢复、之后物理删除。计数型只有进度（允许超额）、没有完成态，只在周期边界复位。**
>
> 本文中的"日期/时刻"示例统一使用本地时区 **Asia/Shanghai（+08:00）**、锚点 `now = 2026-11-01T16:30:00+08:00`（周日）。

## 1. 实体与术语

| 术语 | 定义 |
|---|---|
| 事项 / Event | 唯一领域实体。一条说出来的"要做的事"，落库为 `events` 表一行 |
| 动作标题 | 事项的必填标题；**AI 改写的动作短语**（如"跟张总开会"），不是原话转写 |
| 时间 | 可选。三种精度：仅日期 / 日期+时刻 / 时段（开始–结束）；时段可再带一个截止点 |
| 重复 | 可选。每天 / 每周 / 每月（含间隔、星期几）。**不能没有时间基准** |
| 计数目标 | 可选。次数 + 周期（每天 / 每周）。与"时间""重复"互斥 |
| 未完成 / 已完成 | 仅有的两种状态；已完成用 `completed_at`（单次/无时间型）或完成日志（周期型）表达；**计数型没有完成态，只有进度** |
| 已完成折叠 | 所有视图底部（悬浮窗不含）的折叠区，显示 24 小时内完成的事项/发生次，点击可恢复；计数型不进入 |
| 完成日志 | 周期事项每完成"这一次"写一条记录；用于底部折叠与恢复；24 小时后删除 |
| 本次 occurrence | 周期事项当前等待完成的那一次。事件行始终只保存"当前这一次" |
| 周期边界 | 计数进度的复位边界：每天=本地零点；每周=本地周一 00:00；旧周期进度视为过期 |
| 物理删除 | 从 SQLite 中 `DELETE`，不可恢复。没有回收站、没有备份、没有导出 |
| 视图分组 | 逾期 / 今天 / 以后 / 无时间与打卡 / 已完成。**只是视图分组，不是状态** |

## 2. 字段字典（`events.` 逻辑字段，全文唯一命名）

字段名在本文、AI 契约、存储契约、评估集、测试中**必须逐字一致**。类型为逻辑类型；存储格式见 `storage-schema.md`。

| 字段 | 类型 | 必填 | 精度/格式 | 语义 | 约束（非法值） |
|---|---|---|---|---|---|
| `id` | TEXT | 是 | UUID v7，36 字符 | 主键；本机生成 | 不得为空；不得重复 |
| `title` | TEXT | 是 | 1–120 字符（含中文），单行 | **动作短语**；AI 改写后进入，不是原话；不含时间/数量修饰词 | 空串/纯空白/超长/含换行 → 非法 |
| `due_date` | TEXT | 否 | `YYYY-MM-DD`（本地日历日） | "仅日期"精度（全天） | 非法日历日（如 2026-02-30）→ 非法；与 `due_start_at` 互斥 |
| `due_start_at` | TEXT | 否 | ISO 8601 UTC，`YYYY-MM-DDTHH:MM:SSZ` | 日期+时刻：开始时刻；时段：开始时刻。秒固定 `00` | 无偏移/非 UTC/秒非 00 → 非法；只可有 `due_start_at` 无 `due_end_at`（=时刻型） |
| `due_end_at` | TEXT | 否 | 同上 | 时段结束时刻 | 必须有 `due_start_at`；必须 `> due_start_at` |
| `deadline_at` | TEXT | 否 | 同上 | "时段 + 截止"里的截止点 | **仅当 `due_start_at` 与 `due_end_at` 都存在**；必须 `> due_end_at`；不得单独出现 |
| `repeat_freq` | TEXT | 否 | 枚举 `day` / `week` / `month` | 重复频率 | 枚举外 → 非法；重复**必须**同时有 `due_date` 或 `due_start_at` |
| `repeat_interval` | INTEGER | 否 | 1–99 | 间隔：每 N 天/周/月 | 缺失时按 1；≤0/≥100 → 非法 |
| `repeat_weekdays` | TEXT | 否 | 规范化 JSON 数组，元素 1–7 升序去重（1=周一…7=周日） | 每周的哪几天 | 仅 `repeat_freq = week` 时允许；其他频率必须为 NULL；非 JSON/越界/乱序 → 非法 |
| `count_target` | INTEGER | 否 | 1–99999 | 计数目标次数（本周期） | ≤0 或 >99999 → 非法；与时间字段、重复字段**互斥** |
| `count_period` | TEXT | 否 | 枚举 `day` / `week` | 计数周期 | 枚举外 → 非法；v1 不支持 `month` |
| `count_progress` | INTEGER | 否 | ≥0（**允许超过 `count_target`**，如 4/3） | 本周期已打卡次数；目标值只用于显示参照 | 负数 → 非法；无 `count_target` 时必须为 0；**不设上限** |
| `count_period_key` | TEXT | 否 | 日：`YYYY-MM-DD`；周：`YYYY-Www`（ISO 周） | 当前进度所属周期标识；边界变化即清零 | 与 `count_target` 同生同灭；格式不符 → 非法 |
| `created_at` | TEXT | 是 | 同上（UTC 秒） | 创建时间；系统写入 | 不得为空；系统时间回拨时写 `max(now, created_at)` 规则见 §6.5 |
| `completed_at` | TEXT | 否 | 同上（UTC 秒） | 完成时间；**只有单次/无时间型写它**；为空=未完成 | 周期/计数型必须为 NULL；`completed_at < created_at` → 非法 |

**系统内部列**（不是产品字段）：系统只生成 `id` 与 `created_at`；不存 `updated_at`、`device_id`、`deleted_at`（v1 不同步、不做软删除）。

### 2.1 时间字段组合 → `time_kind`（派生，不存储）

| 字段组合 | `time_kind` | 含义 |
|---|---|---|
| 全为 NULL | `none` | 无时间（想法/待办） |
| `due_date` 非空，其余时间字段为空 | `date` | 仅日期（全天） |
| `due_start_at` 非空、`due_end_at` 为空 | `datetime` | 日期+时刻 |
| `due_start_at` 与 `due_end_at` 均非空 | `range` | 时段；`deadline_at` 非空时 = 时段+截止 |

## 3. 事项形态（派生，不存储）

"类型"不进数据库：一条事项是什么形态，只看字段组合。显示模板只决定摆法，不改变数据。

| 形态 | 判定规则（按顺序） | 说明 | 模板 A（时间轴） | 模板 B（清单） | 悬浮窗 |
|---|---|---|---|---|---|
| **计数型** | `count_target` 非空 | 打卡/习惯类；无时间、无重复；只有进度、无完成态 | 轴下方"打卡"区 | 置底 | 默认不占主区；若显示，点击 = +1（手势 00 §4 已定；是否显示待 Q4） |
| **周期型** | `repeat_freq` 非空 | 有重复规则；事件行保存当前 occurrence | 按当前 occurrence 落在轴上 | 按当前 occurrence 进"今天/以后" | 当前 occurrence 在今天则显示 |
| **单次型** | `repeat_freq` 为空且 `time_kind != none` | 一次性安排 | 按时间落轴 | 逾期/今天/以后 | 今天则显示 |
| **无时间型** | 以上都不满足（时间全空、无重复、无计数） | 想法/待办 | 轴下方"无时间"区 | 置底 | 默认不占主区（是否显示待 Q4） |

状态派生（不建状态列）：

| 派生量 | 计算 |
|---|---|
| `is_done = true`（单次/无时间型） | `completed_at IS NOT NULL` |
| `is_done = false`（周期型事件行） | 事件行始终是当前 occurrence（未完成）；"已完成"由完成日志表达 |
| 计数型 | **没有完成态**：只有进度；`completed_at` 恒为 NULL、不产生日志、不进折叠 |
| `shape` | 计数型 / 周期型 / 单次型 / 无时间型（§3 表） |
| `expires_at` | 单次/无时间型：`completed_at + 24h`；周期型：每条完成日志 `completed_at + 24h`；计数型：**无**（只有周期边界复位） |
| `current_period_key` | 由 `now` + 系统时区推导（日=本地日期；周=ISO 周键 `YYYY-Www`） |
| `is_overdue` | 见 §11.2 |
| `display_*` | 见 §4 |

## 4. 派生显示规则（文案由字段推导，界面不出现"类型"字样）

| 场景 | 规则 |
|---|---|
| 时间文案（仅日期） | 今天 → "今天"；明天 → "明天"；昨天 → "昨天"；7 天内 → "周X"；本年其他 → "M月D日"；跨年 → "YYYY年M月D日" |
| 时间文案（日期+时刻） | 日期部分 + `HH:MM`，如"明天 15:00" |
| 时间文案（时段） | `HH:MM–HH:MM`，如"明天 14:00–16:00" |
| 时间文案（时段+截止） | `HH:MM–HH:MM · 截止 HH:MM` |
| 无时间 | 不显示时间文字（禁止显示"无时间"之类占位） |
| 重复文案 | `day`：`interval=1` → "每天"，否则"每 N 天"；`week` + `weekdays` → "每周一/三/五"（`interval>1` 时"每 N 周…"）；`week` + 无 `weekdays` → "每周"/"每 N 周"；`month` → "每月"/"每 N 月" |
| 计数文案 | `progress/target · 每天` 或 `progress/target · 每周`；**允许超过目标**，如"4/3 · 每天"；达标/超额的视觉强调由 `12-visual-spec.md` 决定，但不得呈现"已完成"折叠语义 |
| 已完成倒计时 | `expires_at - now` 向上取整到小时；<1 小时显示"不足 1 小时"；文案形如"约 23 小时后自动清除" |
| 计数不折叠 | 计数型永不进入"已完成"折叠、不显示 24h 倒计时；周期边界后自动回到 `0/target` |
| 逾期标记 | 由 `is_overdue` 决定样式；**不是状态**，不得出现"逾期"状态列 |
| 标题 | 永远显示 `title`（动作短语）；不显示原话、不显示 AI 标记 |

**禁止的"显示层补默认"**：无时间不补"今天/稍后"；无时段不补时长；未说重复不补"每天"；未说数量不补 1。显示什么，只能是字段里有的东西。

## 5. 两状态与生命周期

### 5.1 状态迁移（唯一状态图）

```
                       完成（单次/无时间型：写 completed_at）
   ┌────────────┐  ─────────────────────────────────────►  ┌─────────────────────┐
   │   未完成    │                                          │ 已完成（底部折叠）    │
   │  open      │ ◄───────────────────────────────────────  │ done                │
   └────┬───────┘        恢复（≤24h：completed_at=NULL）      └──────────┬──────────┘
        │                                                                  │ 24h 到期
        │ 详情删除（立即）                                                  ▼
        ▼                                                          物理删除（DELETE）
   物理删除（DELETE，不可恢复）
```

- 周期型：事件行**永远是"未完成"**（保存当前 occurrence）；完成写入完成日志并推进，日志进入底部折叠。
- 计数型：**没有完成态**；只有本周期进度（可超过目标），周期边界复位，**不做删除、不进折叠**（§8）。
- "逾期 / 今天 / 以后"只是视图分组（§11），与状态无关。

### 5.2 分形态生命周期表

| 形态 | 完成动作 | 完成时发生什么 | 已完成可见期 | 恢复 | 到期处理 |
|---|---|---|---|---|---|
| 单次型（date/datetime/range） | 主窗行首圆圈 / 悬浮窗点任务 | `completed_at = now` | 24 小时（`completed_at+24h` 前） | 底部折叠点击 → `completed_at = NULL` | **物理删除该行** |
| 无时间型 | 同上 | `completed_at = now` | 24 小时 | 同上 | **物理删除该行** |
| 周期型 | 同上 | 写一条完成日志（快照当前 occurrence）+ 推进事件到下一次 | 24 小时（每条日志） | 仅**最新一条**日志且 ≤24h：删日志并把事件回到该 occurrence | 删除完成日志（≥24h）；**系列行永不因完成而删除** |
| 计数型 | 点一下 = `+1`（不是完成） | `count_progress+1`，**可超过 `count_target`（如 4/3）**；无完成态、不写 `completed_at`、不进折叠 | 不适用（无完成态；进度保留到周期边界） | 不适用（可继续 +1，没有"恢复"动作） | 周期边界：`progress=0`、`count_period_key=当前键`；任务保留，**不做删除**（无 24h 记录） |

### 5.3 状态迁移表（触发 → 前置 → 结果 → 异常）

| # | 触发 | 前置 | 结果 | 异常处理 |
|---|---|---|---|---|
| T1 | 完成单次/无时间型 | 未完成 | `completed_at=now`，进底部折叠 | 已完成后重复完成 → 幂等返回成功，不覆盖 `completed_at` |
| T2 | 恢复单次/无时间型 | 已完成且 `now < completed_at+24h` | `completed_at=NULL`，按时间排序回到对应分组 | 超 24h（行已不存在）→ 前端隐藏入口；后端返回 404/409 |
| T3 | 完成周期型本次 | 事件行存在（周期型） | 写日志（occurrence 快照 + `completed_at=now`）；事件推进到下一次 occurrence | 推进计算失败/超上限 → 保持原 occurrence（不写日志），返回错误并提示重试 |
| T4 | 恢复周期型 | 该事件**最新**完成日志且 `now < log.completed_at+24h` | 删除该日志；事件 occurrence 字段 = 日志快照 | 存在更新的日志 → 拒绝（409）；日志已超 24h → 拒绝 |
| T5 | 删除周期型（详情） | 未完成 | **只删"本次"**：不写日志，直接推进到下一次；系列保留 | 推进后仍早于 `now`（欠账）→ 继续推进到 ≥ now（同 T3 跳过期规则） |
| T6 | 删除单次/无时间/计数型（详情） | 未完成 | 立即物理删除整行 | 已完成项不提供删除入口（只能恢复或等 24h 清理） |
| T7 | 计数 +1 | 计数型 | `progress+1`（0 起，**可超过 target**，如 4/3） | 跨周期旧数据：先按当前周期键复位再 +1；连点每次 +1，不封顶 |
| T8 | 计数达标/超额 | 计数型且 `progress >= target` | 仅显示进度变化（如 4/3）；**不写 `completed_at`、不进折叠、不删除、无"恢复"** | 目标只是显示参照，不改变状态机 |
| T9 | 周期边界 | 计数型且 `count_period_key <> 当前周期键` | `progress=0`、`count_period_key=当前键`（懒复位 + 清理作业兜底）；旧周期进度过期 | 应用未运行错过边界：下次启动/任意读写时先复位（读路径也按当前键判定） |
| T10 | 24h 清理 | 单次/无时间型已完成 ≥24h 或日志 ≥24h | 物理删除行/日志 | 失败不阻塞，下个周期重试；幂等 |
| T11 | 编辑（标题/时间/重复/计数） | 未完成 | 见 §10 编辑规则；不合法组合拒绝保存 | 编辑已完成项 → 不允许（先恢复） |

## 6. 时间与时区规则

1. **存储**：所有"时刻"存 UTC（`...Z`，秒=00）；`due_date` 存**本地日历日**（不带时区）。AI 输出带偏移的 ISO 时间，客户端按偏移换算为 UTC 后落库。
2. **显示**：时刻按系统当前时区换算成本地时间显示；`due_date` 原样按本地日历日显示。
3. **精度**：用户输入精度到**分钟**；秒固定 00；相对偏移结果向下取整到分钟。
4. **相对时间基准**：由 AI 输入契约的 `now` + `timezone` 计算；`now` 取捕捉发起瞬间。相对日规则：
   - "今天/明天/后天/大后天" → 本地日历日加减；
   - "周X / 本周X" → 当前 ISO 周（周一为一周之始）内该星期几；若该日已过，取**未来最近**的该星期几（对 date 型可含今天）；
   - "下周X / 下下周X" → 下一 / 下两个 ISO 周；
   - "X月X号" → 本年的该日历日；若已过则仍按本年解析（**不自动顺延到明年**，是否编造由 AI 与用户确认，v1 不做跨年推断）；
   - "N 小时后 / N 分钟后 / N 天后 / 半小时后" → `now` 上加 N；
   - "X 前 / 最晚 X / 截止 X" → 作为日期/截止点解析（见 §6.6）。
5. **时钟**：以本机系统时钟为准。写入 `completed_at` 时若系统回拨导致早于 `created_at`，取 `max(now, created_at)`；时钟前跳可能使 24h 清理提前，接受（单机、无同步）。
6. **边界**：
   - 日边界 = 本地 00:00；
   - 周边界 = 本地周一 00:00（ISO 周，周键 `YYYY-Www`，如 `2026-W44`）；
   - 月边界（仅用于 `repeat_freq=month` 推进）= 每月 1 日 00:00；
   - **不做**"月底/周末/节假日/农历/节气"解析。
7. **时区变化**（如用户改系统时区）：已存 UTC 时刻不重算，显示随新时区变化；`due_date` 日期不变；计数 `count_period_key` 按新时区在下次读写时重新判定，可能立即触发一次边界重置（可接受，v1 单机）。
8. **夏令时**：v1 只保证 Windows 系统时区下的正确本地日历运算；不存在/重复的本地时刻按系统时区库解释（前移到存在时刻 / 取第一个），作为已知边界，不专门做 UI。

### 6.6 "时段 + 截止"的解析语义

- 时段 = `due_start_at` + `due_end_at`；"最晚 X 前 / 截止 X"若明确且晚于 `due_end_at` → 写入 `deadline_at`。
- 只有"截止"没有"时段"时，**不解析**为 `deadline_at`（`deadline_at` 只依附于时段）。`deadline_at` 永远不单独出现。

## 7. 周期型：当前 occurrence、完成日志、下一次计算

### 7.1 模型

- 事件行**只保存当前这一次**（`due_*` 字段 = 当前 occurrence 的时间）；过去/未来的其它 occurrence 不预生成多行。
- "完成本次" = 写一条 `event_completions` 完成日志（快照本次时间）+ 把事件推进到下一次。
- 完成日志字段（逻辑）：`id`、`event_id`、`occurrence_due_date`、`occurrence_start_at`、`occurrence_end_at`、`occurrence_deadline_at`、`completed_at`。日志不存 title（标题以事件行为准）。
- **错过不补**：应用未运行导致多次错过，不生成多条欠账；事件仍只保留当前 occurrence（可能已逾期），完成/删除时按 §7.3 跳过期。

### 7.2 完成日志的 24h 语义

- 每条日志在 `completed_at + 24h` 前出现在**主窗**所有视图底部"已完成"折叠区（悬浮窗不含折叠，Q13），点击=恢复（T4）。
- 超过 24h → 物理删除日志（完成历史不保留、不导出、不统计）。
- 周期事件行本身**永远不会**因完成而进入 24h 清理。

### 7.3 下一次 occurrence 计算（从当前 occurrence 推进一次）

记当前 occurrence 的本地日期为 `D`、记录时刻为 `T`（datetime 的 `start`；range 的 `start/end/deadline` 各自平移）。全部按**本地日历**计算，推进后保持本地时刻不变（换算回 UTC 存储）。

| `repeat_freq` | `repeat_weekdays` | 推进规则 |
|---|---|---|
| `day` | — | `D' = D + repeat_interval 天` |
| `week` | 有值（如 `[1,3,5]`） | 1) 在 `D` 所在 ISO 周内，取 `weekdays` 中 **大于** `D` 星期三的最大最小者（即本周之后最近的选中日）；<br>2) 若本周已无更晚的选中日：跳到 `D 所在周周一 + repeat_interval*7 天`，取该周内最小的选中星期几；<br>3) 结果 `D'` 一定 `> D`。 |
| `week` | NULL | `D' = D + repeat_interval*7 天`（同一星期几） |
| `month` | — | `D' = D + repeat_interval 个月`，日取 `min(D 的日, 目标月最后一天)`（如 1/31 → 2/28） |

- **跳过期规则**：正常完成一次只推进一次；但若推进后 `occurrence` 的结束点（datetime=开始时刻；range=截止点/结束点；date=当天 23:59:59 本地）仍早于 `now`，继续按上表推进，直到 ≥ `now` 或达到安全上限 1000 次（防死循环）；中途不写完成日志。
- **不允许** `repeat_freq=month` + `repeat_weekdays`；不允许"每年/每 N 年/工作日/周末"等未确认频率。
- 周期事件的时间基准必须存在：`repeat_freq` 非空时 `due_date` 或 `due_start_at` 至少一个非空（否则整条非法）。

### 7.4 恢复（T4）

- 仅允许恢复**该事件最新一条**完成日志，且 `now < log.completed_at + 24h`。
- 恢复 = 删除该日志 + 事件 occurrence 字段恢复为日志快照（事件回到未完成，按该 occurrence 的分组显示）。
- 若该事件已有更新的日志（说明之后又完成过），拒绝恢复（409），防止时间线错乱；先恢复更新的那条（或等对方清理）。
- 恢复不改变系列规则本身（`repeat_*` 不变）。

### 7.5 删除"本次"与结束系列

- **删除本次**（T5）：不写日志，直接按 §7.3 推进到下一次；系列保留。被删的这一次**不可恢复**（无撤销）。
- **结束整个系列**：v1 不提供单独"结束重复"字段。路径 = 在详情抽屉把"重复"改为"无"（事件变为单次型，保留当前 occurrence），再删除该条。若只清空时间而保留重复 → 非法组合，拒绝保存（§13）。
- 周期事件在"全部"视图中**只显示当前 occurrence 一条**，不展开未来 N 次。

## 8. 计数型：进度、周期键、边界复位

### 8.1 字段与语义

| 字段 | 语义 |
|---|---|
| `count_target` | 本周期目标次数（1–99999），仅作显示参照 |
| `count_period` | `day`（每天循环）/ `week`（每周循环）。**不支持 month** |
| `count_progress` | 本周期已打卡次数（≥0）；**允许超过 `count_target`**（如 4/3），不设上限 |
| `count_period_key` | 当前进度所属周期：日=`YYYY-MM-DD`；周=`YYYY-Www`（ISO 周，周一为始） |

- 计数型**没有**时间字段、**没有**重复字段、**不写** `completed_at`、**不产生**完成日志、**不进**已完成折叠、**不因达标删除**。
- `count_target` 是"目标"而不是"上限"：超过目标仍是正常进度（4/3），只是没有额外完成语义。
- 计数任务本身是"按周期循环"的（`day` = 每天重新开始；`week` = 每周重新开始），周期即它的节律，不需要 `repeat_*`。

### 8.2 操作

| 操作 | 行为 |
|---|---|
| 点一下（+1） | `progress = progress + 1`（不封顶；达到/超过 target 只影响显示） |
| 恢复 | **不存在**（没有完成态可恢复；可继续 +1，或等周期边界自动复位） |
| 编辑 target | 保留当前 `progress`（目标只是参照，不重置） |
| 编辑 period | `progress = 0`、`count_period_key = 当前周期键`（周期语义变化必须复位） |
| 删除 | 立即物理删除整行，不可恢复 |
| 周期边界 | `progress=0`、`count_period_key=当前周期键`。由清理作业批量复位 + 读路径按当前键判定（懒复位）双保险；旧周期进度视为过期 |

### 8.3 周期键推导（示例，本地时区 Asia/Shanghai）

| now（本地） | `count_period=day` → 键 | `count_period=week` → 键 |
|---|---|---|
| 2026-11-01 16:30（周日） | `2026-11-01` | `2026-W44` |
| 2026-11-02 00:00（周一） | `2026-11-02` | `2026-W45` |
| 2026-12-31 23:59 | `2026-12-31` | `2026-W53` |

- 周键按 ISO 8601：周一开始，包含当年第一个周四的周为第 1 周；`2026-11-01` 属 `2026-W44`。
- 周一边界：`2026-11-01`（周日）的计数在 `2026-11-02 00:00` 复位为 0。

### 8.4 计数型的显示

- 永远在"无时间与打卡"分组（轴下方 / 清单置底）；不占时间轴；是否占悬浮窗主区待 Q4（若显示，点击 = +1）。
- 显示 `progress/target · 每天`（或每周）；超过目标照常显示 `4/3`，**不进入折叠、无 24h 倒计时**；达标/超额的视觉强调由 `12-visual-spec.md` 决定，但不得出现"已完成"语义。
- 周期边界后自动回到 `0/target`，任务本身保留；没有"恢复"入口。

## 9. 已完成折叠、24 小时与物理清理

### 9.1 可见/可恢复窗口

- 单次/无时间型：`[completed_at, completed_at + 24h)` 内出现在底部折叠且可恢复；`>= +24h` 物理删除。
- 周期型：每条完成日志同理（各算各的 24h）；事件行不受影响。
- 计数型：**不参与** 24h 折叠与删除；进度保留到周期边界后自动复位为 0，任务本身保留。
- 悬浮窗**不含**"已完成"折叠（Q13 已确认）。
- 折叠区默认收起；显示条数与展开交互由 `02-ux-spec.md` 决定；**数据规则**：按 `completed_at DESC` 排序，最新完成在最上。

### 9.2 清理作业（领域规则）

触发时机：应用启动完成后一次；运行中每 60 分钟一次；系统从睡眠/休眠恢复后补一次。单飞（同一时刻只跑一个实例），每步独立事务、幂等，失败下轮重试且不阻塞 UI。

执行顺序（同一轮内）：

1. **清理单次/无时间型已完成行**：`completed_at` 非空、且 `repeat_freq IS NULL`、`count_target IS NULL`、`completed_at <= now-24h` → `DELETE`。
2. **清理完成日志**：`event_completions.completed_at <= now-24h` → `DELETE`。
3. **计数周期重置**：`count_target` 非空且 `count_period_key <> 当前周期键` → `progress=0`、`count_period_key=当前键`（按 `period` 分别用日键/周键）。
4. 以上全部完成后写入本地维护时间戳（不涉及用户内容）。

- 清理**只删**上述两类数据；绝不删除：周期事件行、计数事件行、未完成事项、设置。
- **计数型永不参与 24h 删除**：无完成态、无完成日志，只做周期边界复位（§8）。
- 清理与界面判定使用**同一阈值**（`completed_at + 24h`），避免"界面已消失但数据还在"或反之。
- 物理删除后不可恢复：**无回收站、无备份、无导出**（`00-product-decisions.md` v1.2 §7/D14）。

## 10. 创建、编辑与删除

### 10.1 创建（AI 解析结果落库）

- 一次捕捉可能产生 1–5 条事项（AI 契约硬上限 5）；每条独立落库，互不合并、无批次撤销。
- 标题/字段完全来自 AI 输出（经契约校验与语义校验）；**失败时的兜底已确认（Q9）**：标题 = 原文去语气词/填充词、≤120 字，时间/重复/计数为空，只建 1 条（详见 `ai-json.md` §7.3）。
- 原文不落库、不支持"重新解析"（Q10 已确认）；失败只保留解析后事项，不做重解析队列。
- 计数型落库时初始化 `count_progress=0`、`count_period_key=当前周期键`。
- 周期型落库时 `due_*` = AI 给出的首次 occurrence；不写 `completed_at`。

### 10.2 编辑（详情抽屉，仅未完成项）

| 编辑内容 | 规则 |
|---|---|
| 标题 | 1–120 字符；空白拒绝 |
| 时间 | 可改为无时间/仅日期/日期+时刻/时段（+截止）；校验 §2 约束 |
| 重复 | 仅当时间基准存在时允许；设置 `repeat_freq/interval/weekdays`；不提供"截至日期（until）" |
| 计数 | 设置 target/period；改 target 保留 `progress`；改 period 则 `progress=0`、周期键=当前键；与时间/重复互斥 |
| 清空时间 | 若该事项有重复 → 必须同时清空重复；否则拒绝保存（非法组合） |
| 形态切换 | 按 §13 矩阵校验；不合法拒绝保存并提示，不做"自动删除其它字段"的静默修补（计数切换除外，见上） |
| 已完成项 | 不可编辑（先恢复） |

### 10.3 删除

- 入口：右侧详情抽屉；**删除不可恢复，无撤销**。
- 单次/无时间/计数型：删除整行（周期完成日志随外键级联删除）。
- 周期型：**只删"本次"**（§7.5），系列保留并推进。
- 已完成项：不提供删除入口（只能恢复，或等 24h 清理）。

## 11. 视图分组与排序规则

### 11.1 分组（未完成；两个模板同源）

| 分组 | 判定 |
|---|---|
| 逾期 | `is_overdue = true`（§11.2） |
| 今天 | 未逾期，且时间落在本地今天（date=`今天`；datetime 开始于今天；range 与今天相交；周期取当前 occurrence） |
| 以后 | 未逾期、且时间晚于今天结束（含未来日期的周期 occurrence） |
| 无时间与打卡 | 无时间型 + 计数型（置底，永不逾期） |

- 已完成：所有视图底部**折叠区**（单次/无时间 24h 内；周期完成日志 24h 内）；**计数型不进入折叠**；悬浮窗不含折叠（Q13 已确认）。
- 模板 B"今天"范围（**临时默认，Q4 待确认，见 §1.3**）= 逾期 + 今天 + 无时间与打卡（保证无时间事项可达：产品没有收件箱）；"全部" = 上述四组全部。
- 模板 A"一天"：时间轴按时刻摆；时段完整成块；轴下方放"无时间与打卡"。
- 模板 A"7 天"：从本地今天起连续 7 个自然日，每天一列；跨天 range 在相交的每一天都出现（完整不裁剪，视觉由 UX 决定）。
- 模板 A"日历"：月网格；每格最多显示 3 条（按时间排序），点击某天弹出当天清单（当天清单范围 = 模板 B"今天"的当天版）。
- 悬浮窗（只有"一天"）：逾期 + 今天，最多 5 条；无时间与打卡是否进入主区待 `02-ux-spec.md` Q4（数据层不限制；若计数任务显示，点击 = +1）；**悬浮窗不含"已完成"折叠（Q13 已确认）**。

### 11.2 逾期判定

| `time_kind` | 逾期条件 |
|---|---|
| `none` | 永不逾期 |
| `date` | `due_date < 本地今天` |
| `datetime` | `due_start_at < now` |
| `range` | `deadline_at` 存在时：`deadline_at < now`；否则 `due_end_at <= now`（**进行中的时段不算逾期**） |

计数型永不逾期（按周期清零）；周期型按当前 occurrence 的时间判定。

### 11.3 排序（稳定、确定性；同键用 `created_at ASC, id ASC` 兜底）

| 位置 | 排序 |
|---|---|
| 逾期组 | 时间升序（最早的在最上；date 型按当天 00:00 参与比较） |
| 今天组（模板 B） | 仅日期型在前（按 `created_at ASC`），其后 datetime/range 按开始时间升序 |
| 今天组（模板 A 一天） | 由时间轴位置决定；同一时刻按 `created_at ASC, id ASC` |
| 以后组 | 时间升序 |
| 无时间与打卡 | 计数型在前（period=day 先于 week，再按 `created_at ASC`），无时间型随后（`created_at ASC`） |
| 已完成折叠 | 单次/无时间型按 `completed_at DESC`，周期型按日志 `completed_at DESC`（最新在上）；**计数型不在折叠内** |

- 编辑后不保留手工排序（v1 无手动排序字段）。
- 任何视图都不得因分组产生"同一事项出现两次"（跨天 range 在"7 天/日历"按天出现是同一事项的展示，不算重复数据；模板 B 只出现一次）。

## 12. 业务规则用例表（输入 → 行为 → 异常）

| ID | 场景/输入 | 前置 | 行为 | 异常/边界 |
|---|---|---|---|---|
| U01 | "明天下午三点跟张总开会" | — | 创建单次型：`title=跟张总开会`、`due_start_at=2026-11-02T07:00:00Z`（本地 15:00） | 时间解析错误→按契约重试/规则兜底 |
| U02 | "买牛奶" | — | 创建无时间型：时间全空；进"无时间与打卡"组 | 不得补默认时间 |
| U03 | "明天下午两点到四点布置会场，最晚五点前弄完" | — | 创建时段型：`due_start_at/end_at` + `deadline_at`（17:00） | deadline 早于 end → 非法 |
| U04 | "每天下午三点喝咖啡" | now=16:30 | 创建周期型：当前 occurrence=明天 15:00，`repeat_freq=day, interval=1, weekdays=NULL` | 无时间基准的"每天"→ 不解析重复 |
| U05 | "每天三杯水" | — | 创建计数型：`count_target=3, count_period=day, progress=0, period_key=2026-11-01` | 计数与时间/重复同时出现→按契约只保留一种 |
| U06 | 完成 U01 | 未完成 | `completed_at=now`；进底部折叠，24h 倒计时 | 重复点击→幂等 |
| U07 | 恢复 U06 | 完成 ≤24h | `completed_at=NULL`，回"今天/明天"分组 | 超 24h→行已删除，入口不存在 |
| U08 | 完成 U04 | 周期型 | 写日志（occurrence=明天 15:00）+ 事件推进到后天 15:00；日志折叠可恢复 | 推进失败→不写日志，报错重试 |
| U09 | 恢复 U08 的日志 | 最新日志且 ≤24h | 删日志；事件回到"明天 15:00" | 存在更新日志→409 拒绝 |
| U10 | 删除 U04（周期型） | 未完成 | 不写日志、不产生 24h 记录；事件推进到下一次 | 被删的这一次不可恢复 |
| U11 | 删除 U01（单次型） | 未完成 | 立即物理删除整行 | 无撤销；日志（若有）级联删除 |
| U12 | 计数 +1 三次 | target=3 | 第三次后 `progress=3`；第四次 `progress=4`（显示 4/3，允许超额） | **不折叠、不写 completed_at、不删除**；无"恢复"入口 |
| U13 | 计数超额与展示 | target=3, progress=4 | 显示 `4/3 · 每天`；无完成态样式 | 周期边界后自动回到 `0/3` |
| U14 | 计数跨零点 | `period=day`，key=昨天 | 任意读取/写入先按当前日键重置；清理作业批量重置 | 应用关闭期间跨边界→启动时重置 |
| U15 | 计数跨周一零点 | `period=week` | 周键从 `2026-W44` → `2026-W45`，`progress=0` | 周日 23:59 的进度 → 周一 00:00 复位（非"完成态消失"） |
| U16 | 编辑周期事件，清空时间 | 有重复 | 拒绝保存（重复必须有时间基准） | UI 提示，不静默改数据 |
| U17 | 编辑计数 target 3→5 | `progress=2` | 保存后 `progress=2` 保留（目标只是参照）；若改 period 则 `progress=0` | 不允许跨周期残留 |
| U18 | 编辑已完成项 | 已完成 | 不允许；只能恢复 | — |
| U19 | 双击完成 | 未完成 | 两请求串行/幂等，`completed_at` 只写一次 | 并发下用条件 UPDATE 保证 |
| U20 | 24h 边界 | 已完成 23:59:59 前 | 折叠区仍可见可恢复 | 到点后同一阈值删除，界面与数据一致 |
| U21 | 系统时钟回拨后完成 | — | `completed_at = max(now, created_at)` | 不产生 `completed_at < created_at` |
| U22 | 改系统时区后查看 | 已有事项 | datetime 显示按新时区；`due_date` 不变；计数按新时区重判周期 | 可能立即触发一次周期重置 |
| U23 | range 进行中（14:00–16:00，now=15:00） | 未完成 | 显示"进行中"样式，不算逾期 | 16:00 后仍可完成，之后才逾期 |
| U24 | 日历某天 >3 条 | — | 格子最多 3 条 + "更多"入口；点击弹出当天清单 | 当天清单不裁剪 |
| U25 | 系统时钟前跳 10 天 | 有已完成项 | 24h 清理提前执行（按新 now 判定） | 接受（单机、无同步）；不可恢复 |
| U26 | 迁移后列值非法（如 count+time 并存） | 异常数据 | 打开时校验失败 → 不崩溃；按 §13 矩阵拒绝并提示数据损坏 | 见 storage-schema 迁移/校验章节 |

## 13. 不合法组合与边界

### 13.1 字段组合矩阵（存储层 CHECK + 应用层双层校验）

| # | 组合 | 合法? | 处置 |
|---|---|---|---|
| C01 | 计数型 + 时间字段 | ❌ | 拒绝写入。解析侧规则：有明确时钟时间时按单次/周期型解析，不解析计数 |
| C02 | 计数型 + 重复字段 | ❌ | 拒绝写入；"每天3次"用 `count_period=day` 表达，不用 `repeat_*` |
| C03 | 重复 + 无时间基准 | ❌ | 拒绝写入；解析侧不解析重复，仅保留明确的时间部分（或 none） |
| C04 | `deadline_at` 无 `due_end_at` | ❌ | 拒绝；截止只依附时段 |
| C05 | `due_end_at` 无 `due_start_at` | ❌ | 拒绝 |
| C06 | `due_date` 与 `due_start_at` 并存 | ❌ | 拒绝（精度唯一） |
| C07 | `due_end_at <= due_start_at` | ❌ | 拒绝 |
| C08 | `deadline_at <= due_end_at` | ❌ | 拒绝 |
| C09 | `repeat_weekdays` 且 `repeat_freq != week` | ❌ | 拒绝 |
| C10 | `repeat_freq=month` + `weekdays` | ❌ | 拒绝（月度不支持多日） |
| C11 | `repeat_interval` 缺失 | ✅ | 归一为 1 |
| C12 | 周期型/计数型写 `completed_at` | ❌ | 拒绝；周期完成只写日志，计数型永远没有完成态 |
| C13 | `count_progress > count_target`（如 4/3） | ✅ | **允许**；目标只是显示参照，+1 不封顶 |
| C14 | `count_period` 非 day/week（如 month） | ❌ | 拒绝；v1 不支持月计数 |
| C15 | `count_period_key` 格式错/与 period 不匹配 | ❌ | 拒绝 |
| C16 | `completed_at < created_at` | ❌ | 写入时取 `max(now, created_at)` |
| C17 | 标题空/纯空白/超 120 字符/多行 | ❌ | 拒绝 |
| C18 | `id` 空/重复 | ❌ | 拒绝 |
| C19 | `repeat_until`（重复截止） | ❌ | v1 无此字段；结束系列用"重复改无 + 删除" |
| C20 | 提醒字段 / 标签 / 备注 / 优先级 / 清单 | ❌ | v1 无此字段，出现即契约违规 |

### 13.2 数据边界

| 边界 | 规则 |
|---|---|
| 单次捕捉条数 | 1–5 条；>5 条按 AI 契约取前 5 |
| 标题长度 | 1–120 字符（按 Unicode 字符计） |
| 计数目标 | 1–99999；`progress` **允许超过 target**（如 4/3）、从 0 起不封顶；DB 只要求非负 |
| 重复间隔 | 1–99；`month` 目标月缺失日 → 取当月最后一天 |
| 日期范围 | 支持本地 2000-01-01 ~ 2099-12-31；超出视为解析失败（契约层校验） |
| 24h 窗口 | 半开区间 `[completed_at, completed_at+24h)`；清理与显示同阈值；计数型不参与 |
| 周期边界 | 懒复位 + 清理作业双保险；读路径不得显示旧周期进度（视为过期） |
| 并发 | 单机单实例；完成/恢复/+1 用条件 UPDATE 防重复；无跨进程竞争 |
| 数据丢失 | 无备份/导出/回收站：物理删除与库损坏均不可恢复（风险 R6 已接受，见 `10-risks-decisions.md`） |
