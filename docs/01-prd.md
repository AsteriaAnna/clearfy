## 1. 产品定义摘要

**一句话**：Clarify 是一个不需要部署服务器的 Windows 桌面极简 AI 待办——按一个热键说一句，云端 ASR + DeepSeek 把它解析成「动作标题 + 明确字段」的待办，**直接落进视图**；点一下完成，已完成项在底部折叠、24 小时内可恢复、之后物理删除。

核心不变量（任何功能设计都不得违反）：

| # | 不变量 | 来源 |
|---|---|---|
| I1 | **捕捉零决策**：捕捉路径上用户只做"说/写"一个动作，不弹确认、不追问、不要求选分类 | 00 §3.4、§7 |
| I2 | **无收件箱/无标签/无项目**：解析结果直接落视图，没有缓冲区、没有待整理池 | 00 §1 |
| I3 | **只有未完成 / 已完成两状态**；逾期/今天/以后只是视图分组 | 00 §4 |
| I4 | **已完成在底部折叠、24h 内可恢复、之后物理删除**；删除（详情抽屉）不可恢复 | 00 §4 |
| I5 | **AI 只提取明确内容**：不猜、不补默认、不追问；模糊时间留空 | 00 §3 |
| I6 | **两种显示模板 A 时间轴 / B 清单**，数据同源，模板只决定摆法 | 00 §5 |
| I7 | **主窗 = 一个主页面 + 设置页**；悬浮窗是独立精致小组件 | 00 §6、§5 |
| I8 | **不做系统通知、不做首次引导、不做备份导出** | 00 §1、§9（v1.1） |
| I9 | **无自建服务器/无账号**；数据只在本机 SQLite | 00 §9 |

## 2. 用户与核心场景

### 2.1 目标用户

25~40 岁知识工作者，Windows 笔记本，事情多且碎片化；用过滴答清单/Todoist 等工具但坚持不下来（整理成本 > 收益）。核心诉求：**想到就说、说完就忘、打开就能看见今天要做什么、点一下就没**。
（沿用 Charter v1.1 §4 的用户画像与场景方向，取其中 3 个核心场景；删去旧版"清收件箱"表述。）

### 2.2 核心场景（共 3 个）

**场景 1｜工作中想起一件事（捕捉闭环）**
正在写代码/开会，想起"明天下午三点跟张总开会，顺便买牛奶"。按 `Ctrl+Alt+Space` → 捕捉条出现即开麦 → 说完（或直接打字）→ 提交。AI 拆成两条：`跟张总开会`（时间：明天 15:00）、`买牛奶`（无时间）→ **直接落进视图**，不弹确认、不要求整理 → 用户 3 秒内回到手上的事。
成功标准：热键到捕捉条 < 150ms；提交到结果落位 ≤ 4s（P95，网络正常）；全程 0 次确认。

**场景 2｜坐在电脑前消费待办（完成闭环）**
悬浮窗就是"今天的台面"：一眼看到今天时间轴或清单 → 点任务/点行首圆圈 = 完成 → 该条 ≤1 秒内从悬浮窗消失并进入底部"已完成"折叠；计数任务点一下 +1（如"喝水 2/3"），到零点/周一零点自动清零。
成功标准：完成 0 次确认；已完成折叠可展开、24h 内点击可恢复。

**场景 3｜回看与调整（主窗管理）**
打开主窗 → 顶部切模板 A（一天/7天/日历）或 B（今天/全部）→ 7 天找出冲突、日历点某天弹出当天清单；点任务行 → 右侧详情抽屉改标题/时间/重复/计数，或删除（不可恢复）；在底部已完成折叠里恢复误点完成的事项；在设置里用"截图式拖选"分别配置主窗与悬浮窗的时间范围。
成功标准：数据同源、两模板一致；所有编辑在抽屉完成、不跳页；已完成恢复 ≤1 次点击。

### 2.3 非目标场景（v1 不做，见 §4）

到点提醒/系统通知、跨设备同步/账号、团队协作、标签/项目整理、数据备份导出、首次运行引导、AI 聊天或 AI 自动执行。

### F1 全局捕捉（P0）

- **用户故事**：作为正在专注工作的用户，我希望按一个热键就能说一句或打一句，以便不切换窗口、不做任何选择就记下一件事。
- **状态**：已定（00 §7：`Ctrl+Alt+Space` 弹出输入条、默认开麦、也可直接打字、`Esc` 取消）。云端 ASR 依据 00 §9（音频发语音识别厂商）。细化细节见 `02-ux-spec.md` §9；待定 Q11。

**行为要点（已定）**
1. 全局热键 `Ctrl+Alt+Space` 唤出**捕捉条**；出现即**默认开麦**，同时**允许直接打字**。
2. `Esc` 取消本次捕捉。
3. 提交后不弹任何确认，结果按 F2 解析后**直接落进视图**（无收件箱）。
4. 语音识别在云端完成（音频发语音识别厂商），本机只负责录音；文字不走 ASR。

**验收标准**
- AC-F1-1 在任意前台应用按 `Ctrl+Alt+Space`，捕捉条出现；热键→可见 **P95 < 150ms**（沿用 Charter v1.1 §5 指标）。
- AC-F1-2 麦克风可用且已授权时，捕捉条出现即进入录音状态，并有可见的"录音中"指示。
- AC-F1-3 用户无需切换模式即可直接输入文字，文字可编辑；文字输入与录音可同时存在，提交时以文字内容为准。
- AC-F1-4 按 `Esc` 关闭捕捉条并取消本次输入，**不创建任何任务**、不残留空白记录。
- AC-F1-5 提交后捕捉条收起，**不出现确认框/追问弹窗**；网络正常时 ≤4s（P95）内任务出现在视图中。
- AC-F1-6 一次提交可产生 1~N 条任务（N 由 F2 拆条决定）；N>1 时用户可感知"创建了 N 项"（反馈形态见 `02-ux-spec.md` §9）。
- AC-F1-7 任何失败路径（离线、ASR 失败、解析失败、额度用尽）都**不静默**：用户能看到明确状态，且已输入的内容不消失（落库与否见 Q9/Q10）。
- AC-F1-8 离线时文字捕捉仍可用；语音捕捉给出明确的"需要联网"提示，不表现为无响应。

**边界情况**
- 麦克风未授权/被其他程序占用：提示原因并保持可打字（提示位置待定 Q11）。
- 全局热键被其他软件占用（注册失败）：必须可感知，不能静默失效（提示方式待定 Q11）。
- 提交空内容：不创建任务，捕捉条不产生空记录。
- 输入超长 / 单次拆条条数上限：待定 Q25。
- 多显示器/高 DPI：捕捉条出现位置与缩放方式待定 Q11。
- 捕捉条打开时重复按热键的行为（忽略 / 结束录音）、录音最长时长：待定 Q11。
- 中文输入法组合态下按 `Esc`：细化规则为先取消输入法组合、再次 `Esc` 才取消捕捉（避免误杀输入）。

### F2 AI 解析（P0）

- **用户故事**：作为不想整理的用户，我希望 AI 把我的一句口语直接变成"动作标题 + 明确的时间/重复/计数"，没说的就留空，以便我不用编辑就能用。
- **状态**：已定（00 §3 全部规则）。规则兜底（无 AI 时）见 F11。待定 Q9/Q10/Q25/Q28。

**行为要点（已定）**
1. **标题是动作**：AI 把口语改写成"要做什么"的动作短语，界面显示动作而不是原话。
2. **按动作拆条**：一次语音里有多个动作就拆成多条；一条里共用的明确时间，各条继承。
3. **只解析明确内容**：日期、时刻、时段清楚才写入时间字段；"晚上/上午/尽快"等模糊说法**不解析**，时间留空。
4. **不猜、不补默认、不追问**：没说的字段就是空；不弹确认框、不出现"AI 假设"标记或低置信度确认弹窗。
5. **"提醒我"只作时间线索**；本软件不提醒、不产生通知（00 §3.5、§9）。
6. 输入 = 本次捕捉的文本（ASR 结果或手打文字）+ 当前本地时间与时区；输出 = 结构化任务列表（字段见 F3）。

**验收标准**
- AC-F2-1 标题必须是动作短语而非原话：如说"明天下午三点跟张总开会"，标题为 `跟张总开会`（不是整句复述）。
- AC-F2-2 一句话含多个独立动作时，拆成多条（每个明确动作一条）；共用明确时间被各条继承。例："明天下午三点跟张总开会，顺便买牛奶" → 2 条：会议 `明天 15:00`、买牛奶 `无时间`。
- AC-F2-3 模糊时间不解析：出现"晚上/上午/尽快/稍后"等，时间字段为空；不得猜测成 20:00/09:00 等。
- AC-F2-4 未说的时间/重复/计数一律留空，不得补默认值（包括"默认明天""默认 1 小时""默认整天"等任何旧默认规则）。
- AC-F2-5 解析过程 0 次确认、0 次追问、0 次假设提示或低置信度弹窗。
- AC-F2-6 说"提醒我…"时只解析其时间线索，不生成"提醒时间"字段、不产生系统通知。
- AC-F2-7 解析失败（超时/非法输出/供应商错误）时，捕捉不中断、不丢输入、不弹模态框；降级规则见 F11。
- AC-F2-8 评估集上：**时间字段准确率 ≥ 90%**、**幻觉日期 = 0**、**JSON 合法率 ≥ 99%**（沿用 Charter v1.1 §5）。
- AC-F2-9 不得使用用户未说出的信息（历史数据、地理位置、默认时间规则等）来填充字段。

**边界情况**
- 全句没有任何可动作化的内容（纯感叹/疑问）：兜底标题 **Q9 待用户确认**；关闭前的临时默认见 §8（原文去语气、≤120 字、时间空、建 1 条，非确认口径）。
- 单句动作数超过拆条上限：上限待定 Q25；超限时不得静默丢动作（细化：至少保留为 1 条可编辑任务）。
- ASR 识别错误导致语义变化：按 F11 的可编辑兜底处理，不做二次猜测。
- 相对时间（"下周三""月底""半小时后"）必须基于当前本地时间时区解析；时区/系统时间异常见 Q26/§8。
- 原始语音文本是否保留、是否支持"重新解析"：待定 Q10。

### F3 任务（事件）字段与编辑（P0）

- **用户故事**：作为用户，我希望每条待办就是一句"动作 + 需要时的时间/重复/计数"，不要分类和多余字段；并且写错时能在右侧详情里直接改，以便保持数据极简、可修正。
- **状态**：已定（00 §2：字段集、不存类型枚举；00 §7：详情抽屉可编辑标题/时间/重复/计数）。编辑控件与校验待定 Q16；"时段+截止点"语义待定 Q1；字段组合约束 Q8。

**数据模型（用户可见，已定）**

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | 是 | 动作短语（不是原话） |
| 时间 | 否 | 以下形态之一：`仅日期` / `日期+时刻` / `时段（开始–结束）`；允许"时段为主 + 截止点"（语义待定 Q1） |
| 重复 | 否 | 每天/每周/每月等（v1 具体范围待定 Q7） |
| 计数目标 | 否 | 次数 + 周期（如"每天 3 杯"） |
| 创建时间 | 系统记录 | 由系统自动写入，用户不可编辑 |
| 完成时间 | 系统记录 | 完成时由系统写入，用户不可编辑 |

- **不存"类型"枚举**：一条任务是什么形态（单次时点 / 单次时段 / 周期 / 无时间 / 习惯计数）由字段组合推导，显示模板决定怎么摆。
- **v1 不引入任何其他字段**：无备注、无标签、无项目/清单、无优先级/置顶、无提醒时间、无父子/子任务、无金额、无"等待"状态。
- 编辑入口：主窗点任务行 → **右侧详情抽屉**；可编辑标题、时间、重复、计数；**删除**也在抽屉（不可恢复，见 F4/F12）。

**验收标准**
- AC-F3-1 任一任务在数据层只包含上表字段；界面任何位置不得出现收件箱、标签、项目、优先级、提醒时间、备注、子任务等入口或字段。
- AC-F3-2 捕捉创建的任务，字段值只能来自用户明确说出的内容；无时间的任务在视图中按"无时间"处理（A 轴下方 / B 时间文字为空），不得因缺少时间被拒绝创建。
- AC-F3-3 详情抽屉能编辑标题、时间、重复、计数，并在关闭/重启应用后保持修改结果。
- AC-F3-4 标题为空（或仅空白）时不允许保存空标题，给出明确错误提示。
- AC-F3-5 时间编辑支持切换"无时间 / 仅日期 / 日期+时刻 / 时段 / 时段+截止点"；时段形态下结束时间必须晚于开始时间，否则不保存并提示。
- AC-F3-6 编辑后任务在所有视图（A/B、主窗/悬浮窗、日历）同步更新，不出现两套数据。
- AC-F3-7 抽屉内可删除任务；删除需一次明确确认（细化；确认方式见 Q16），确认后立即物理删除、所有视图立即消失（不可恢复，见 F12）。

**边界情况**
- 把有时间的任务改成"无时间"：任务转为无时间形态，落到 A 轴下方 / B 无时间分组。
- 把时间改成过去：任务仍保留，按视图的"逾期"分组呈现（分组规则待定 Q26）。
- 重复/计数与时间的组合（如"每天"但没有日期、计数任务同时有具体时刻）：待定 Q8。
- 长标题在行内截断但抽屉内完整显示（截断规则见 `02-ux-spec.md`）。
- "时段+截止点"的编辑控件与校验规则：待定 Q1。

### F4 完成 / 恢复 / 已完成折叠（P0）

- **用户故事**：作为用户，我希望点一下就算完成，完成项不占视线但又能在 24 小时内找回；超过 24 小时就彻底消失，以便我永远不用做"整理/清理"的决定。
- **状态**：已定（00 §4 全部；00 §5 通用"已完成在底部折叠，点击可恢复"）。恢复细节待定 Q5；折叠交互待定 Q17；**悬浮窗是否含折叠 Q13 待用户确认**（临时默认见 §8）。

**行为要点（已定）**
1. 完成入口：**主窗行首圆圈点击 = 完成**；**悬浮窗点击任务 = 完成**；计数任务点击 = +1（见 F6）。
2. **已完成折叠在主窗所有视图底部**（A/B、今天/全部、主窗子视图），**点击可恢复**；悬浮窗是否同样保留 **Q13 待用户确认**（临时默认：悬浮窗主区不含折叠、完成项 ≤1s 消失，见 §8 与 `10-risks-decisions.md` §3）。
3. 单次 / 无时间任务：完成 → 24 小时内可见、可恢复 → **24 小时后物理删除**。
4. 重复任务：完成的是"这一次" → 记一次完成 → **系列不删**，按重复规则下次再出现；本次完成记录 24 小时后删除（见 F5）。
5. 删除 ≠ 完成：删除在右侧详情抽屉、**删除后不可恢复**（不设撤销）。

**验收标准**
- AC-F4-1 主窗点行首圆圈后，该任务从"未完成"区域消失并进入底部已完成折叠；无确认弹窗。
- AC-F4-2 悬浮窗点击任务后，该任务 **≤1 秒内**从悬浮窗消失（`02-ux-spec.md` §8 体验线；该规则保留范围见 Q24；Q13 未关闭前按临时默认执行）。
- AC-F4-3 已完成折叠默认收起、显示已完成数量；展开后可见 24h 内完成记录；无已完成项时折叠不显示。
- AC-F4-4 在 24h 内点击已完成记录可恢复为未完成（恢复后进入哪个分组/是否保留原时间见 Q5）。
- AC-F4-5 完成时间超过 24h 的任务：所有视图中不可见、不可恢复，**数据被物理删除**（数据库无残留，见 F12）。
- AC-F4-6 对同一任务重复点击完成不产生多条完成记录（幂等）。
- AC-F4-7 完成后不产生任何系统通知、不弹出打扰性确认。
- AC-F4-8 已完成折叠在 A/B 两模板、今天/全部、主窗各子视图底部行为一致（悬浮窗见 Q13）。

**边界情况**
- 应用关闭超过 24h 后再启动：启动时必须已完成清理（不残留可恢复项）。
- 系统时间/时区被修改：24h 计算口径待定 Q26。
- 恢复一个时间已过期的事项：恢复后如何分组待定 Q5/Q26。
- 恢复重复任务的某一次完成记录：语义待定 Q5。
- 已完成记录在折叠内的排序/剩余时间文案：待定 Q17。
- 任务已完成后又被删除（若抽屉可从已完成项打开）：v1 不提供该路径（细化：已完成项点击=恢复，不打开抽屉）。

### F5 重复任务（P1）

- **用户故事**：作为有周期性事务的用户，我希望说"每周一上午十点周会"就能自动按周出现，完成一次就推进到下一次，不用每次重建。
- **状态**：已定（00 §2 重复字段；00 §4 完成本次、系列保留、本次记录 24h 后删除）。v1 支持范围待定 Q7；规则范围外的复杂重复不做（细化）。

**行为要点（已定）**
1. 重复是任务的**可选字段**（每天/每周/每月等，具体支持范围待定 Q7）。
2. 完成重复任务 = 完成"这一次"：记一次完成，**系列本身不删**，按重复规则下次再出现。
3. 本次完成记录 **24 小时后删除**；系列继续。
4. **不弹"本次/整个系列"选择框**（捕捉与完成路径 0 决策，I1）。

**验收标准**
- AC-F5-1 创建"每周一 10:00 周会"后，周一 10:00 视图出现该任务；完成后下次出现时间按重复规则推进（具体规则待定 Q7，但"系列不删"必须成立）。
- AC-F5-2 完成重复任务后，系列任务仍存在（检查下一次出现），本次只产生一条完成记录。
- AC-F5-3 本次完成记录在 24h 后从已完成折叠消失并被物理删除；系列不受影响。
- AC-F5-4 完成重复任务的过程中不出现"本次/整个系列"选择弹窗。
- AC-F5-5 编辑重复规则后，后续出现时间按新规则计算（已生成的完成记录不追溯，细化）。

**边界情况**
- 逾期未完成时再完成本次：下一次如何计算（从今天还是原定日）待定 Q7。
- 月末/闰年（每月 31 日）：待定 Q7。
- 重复 + 无日期/无时刻组合：待定 Q8。
- 如何结束整个系列（抽屉删除是否删除系列）：待定 Q7。
- 重复任务的时间范围跨天（如 23:00 开始）：待定 Q7。

### F6 计数任务（P1）

- **用户故事**：作为有习惯类事项的用户，我希望说"每天喝 3 杯水"就得到一个打卡计数，点一下 +1，到周期边界自动清零，不用手动整理。
- **状态**：已定（00 §2 计数目标 = 次数 + 周期；00 §4 点一下 +1、按周期边界清零、完成状态在边界消失）。细节待定 Q6。

**行为要点（已定）**
1. 计数任务是任务的可选字段：**次数 + 周期**（如"每天 3 杯"、"每周 3 次"）。
2. **点一下 = +1**（主窗行首圆圈在计数任务上=+1；悬浮窗点击任务=+1）。
3. 周期边界：**每天**到零点清零；**每周**到周一零点清零；完成状态在边界消失，下一周期从 0 开始。

**验收标准**
- AC-F6-1 计数任务在视图中显示进度（如 `2 / 3`）与周期（如"每天"）。
- AC-F6-2 点击一次进度 +1；计数任务不因点击而整条消失（除达到目标后的完成态处理，见 AC-F6-3）。
- AC-F6-3 达到目标次数后任务进入"已完成"表现（具体呈现与是否进折叠待定 Q6），并在周期边界回到 0。
- AC-F6-4 每天任务在本地零点后、每周任务在本地周一零点后进度归零（应用关闭期间越过边界，下次启动即归零）。
- AC-F6-5 计数任务按周期清零时，**任务本身（系列）不删除**。
- AC-F6-6 计数任务的完成状态在边界随进度一起消失。

**边界情况**
- 超过目标次数继续点击：待定 Q6。
- 计数任务同时带具体时间/重复：待定 Q8。
- 应用在边界时刻正在运行：必须自动归零，无需用户操作。
- 周期边界使用本地时区；系统时间/时区变更：待定 Q26。
- 计数任务的完成记录是否 24h 物理删除：待定 Q6（与 F12 的物理删除规则需对齐）。

### F7 模板 A：时间轴（P0）

- **用户故事**：作为按时间安排事情的用户，我希望主窗沿着一条时间轴看到今天/7 天/日历上的事，一眼看到时间冲突与空档，悬浮窗也能只看今天。

**边界情况**

### F11 官方 AI 服务：激活 / 额度 / BYOK / 规则兜底（P0）

- **用户故事**：作为不想自己部署服务器的用户，我希望用激活码开通官方 AI 服务、每天有免费额度，额度用尽或断网时借助自带 Key 或本地规则继续用，任何情况都不丢我输入的东西。
- **状态**：已定（00 §9：官方轻量网关为主 + BYOK 兜底 + 规则模式；邀请码 + 每设备每天 200 次 + 月预算 ¥200 告警；隐私边界）。界面呈现待定 Q14/Q15；BYOK 覆盖范围与降级细节待定 Q21；离线语音行为待定 Q27。

**行为要点（已定）**
1. **三种 AI 模式**：官方轻量网关（主）→ BYOK（兜底）→ 规则模式（降级）。
2. **官方服务**：邀请码激活；**每设备每天 200 次**调用额度；**月预算 ¥200 告警**（达 80% 告警、达 100% 停止 AI 调用并提示，D20）。
3. **BYOK**：用户自带模型 Key，官方服务不可用时使用（覆盖范围待 Q21）。
4. **规则兜底**：无网络/无激活/额度用尽/网关异常时，用本地规则解析明确的日期/时间/重复/分句，解析不了的字段留空，**仍创建可编辑任务，不丢输入、不弹模态框**；标题兜底 **Q9 待用户确认**（临时默认见 §8，非确认口径）。
5. **隐私**：音频发语音识别厂商、解析文本发 DeepSeek（00 §9）；需在界面某处明示（位置待 Q15，无首启引导）。
6. 不做后台自动 AI 调用：AI 只在用户捕捉/显式操作时调用（沿用 v1.0 "AI 隐身"主张；技术侧见 `04-architecture.md`，Charter v1.1 已重写不再保留该编号）。

**验收标准**
- AC-F11-1 未激活时，用户可在设置中通过邀请码完成激活；激活成功后有明确的成功状态（额度/模式可感知，呈现待 Q14）。
- AC-F11-2 官方服务可用时，捕捉走官方网关完成 ASR + 解析（不要求用户配置 Key）。
- AC-F11-3 每日额度（200 次/设备）用尽后：捕捉给出明确提示，自动降级（BYOK 或规则模式），**不丢输入、不阻塞**。
- AC-F11-4 月预算达到告警线/上限时：有明确提示；达 100% 时停止官方 AI 调用并降级（D20）。
- AC-F11-5 已配置 BYOK 时，官方服务不可用（额度用尽/网关错误/未激活）可自动使用 BYOK 完成解析。
- AC-F11-6 断网或全部 AI 不可用时，文字捕捉 + 规则解析仍可用：明确写出的日期/时间/重复可被本地解析，其余字段留空，任务被创建为可编辑状态。
- AC-F11-7 任何 AI 失败路径都不出现模态错误框、不静默、不丢用户已输入内容；用户可感知当前处于哪种模式（官方/BYOK/规则）。
- AC-F11-8 隐私告知在界面中存在且可读（位置待 Q15）；不通过首次引导弹窗实现（无首启）。
- AC-F11-9 无后台自动 AI 调用：除用户触发的捕捉与显式操作外，不自动发起 AI 请求。
- AC-F11-10 激活码无效/被吊销/服务不可达时，错误提示可理解，且不影响本地数据与既有任务的浏览/编辑/完成。

**边界情况**

### F12 本地数据与物理删除（P0）

- **用户故事**：作为用户，我希望所有待办只存在我这台电脑上，不需要账号、不需要备份操作；完成 24 小时后就彻底删除，删除的东西绝不留下。
- **状态**：已定（00 §4 物理删除；00 §9 数据只在本机 SQLite、无服务器、无备份导出）。存储位置/清理时机/时间变更待定 Q22/Q26。

**行为要点（已定）**
1. **数据只在本机 SQLite**；无账号、无自建服务器、不同步、**不做数据备份与导出**。
2. 完成记录 **24 小时后物理删除**；单次/无时间任务删除本次完成记录；重复任务只删本次完成记录、系列保留；计数任务按周期边界清零（任务本体保留）。
3. 详情抽屉删除 = **立即物理删除任务本体，不可恢复**（不设撤销/回收站）。
4. 不在本地之外留存任务数据；仅 ASR 音频发厂商、解析文本发 AI 厂商（F11 隐私边界）。

**验收标准**
- AC-F12-1 断网状态下可浏览、编辑、完成本地任务；数据在应用重启后保留。
- AC-F12-2 完成时间 ≥24h 的记录在下次启动/定时清理后从数据库物理删除，任何界面都无法再查到或恢复（自动化验证）。
- AC-F12-3 详情抽屉删除任务后，数据库无该任务残留，任何视图（含已完成折叠）不可恢复。
- AC-F12-4 应用内不存在导出、备份、导入、回收站等入口（00 v1.1）。
- AC-F12-5 任务数据不写入任何自建服务器/云；除 F11 声明的 ASR 音频与解析文本外，无用户任务内容外发。
- AC-F12-6 计数任务的周期清零不删除任务本体；重复任务完成不删除系列（与 F5/F6 联动验证）。
- AC-F12-7 崩溃/异常退出后重启，已保存数据不丢失、不产生重复任务（数据一致性由 03/04 技术文档细化）。

**边界情况**
- 数据存储路径、数据库文件位置、卸载是否保留/删除数据：待定 Q22。
- 24h 到期清理时机（启动时/定时/两者）与系统休眠恢复：待定 Q22。
- 系统时间/时区被修改、跨时区使用：待定 Q26。
- 磁盘写满/数据库损坏：v1 无备份导出，需在错误文案中明确告知（不承诺恢复，待技术文档）。
- 已完成记录被"恢复"后再次完成：产生新的完成时间，24h 重新计时（细化）。

## 9. 对下游文档的约束（防止跨文档漂移）

1. **`03-domain-model.md` 必须遵循 00 §2 + 本文 F3**：字段仅有 `标题 / 时间（仅日期、日期+时刻、时段、时段+截止点）/ 重复 / 计数目标（次数+周期）/ 创建时间 / 完成时间`（+ 技术必需的主键/批次/时间戳等内部字段）；**禁止** `notes`、`remind_at`、`tags`、`pinned`、`status=inbox/active/done/archived`、`archived_at/archived_reason`、`source=inbox`、回收站等旧模型；状态只能表达"未完成/已完成"。
2. **`05-contracts/ai-json.md`**：输出只包含上述事件字段与必要的内部元数据（批次、顺序）；**禁止**补默认值、禁止用户可见的假设/置信度标记、禁止输出提醒/标签/置顶/备注；模糊时间必须留空；必须支持"无时间任务"。
3. **`02-ux-spec.md`**：已作为配套交付；页面结构以"一个主页面 + 设置"为准，不得按旧 6 页/首启 5 步/托盘/通知设计。
4. **`07-test-strategy.md`**：每条 AC 可映射为测试用例；重点覆盖 M9~M14、AC-F5-2、AC-F6-4、AC-F7-5、AC-F7-6、AC-F9-6、AC-F10-5、AC-F11-3/6、AC-F12-2/3/4。
