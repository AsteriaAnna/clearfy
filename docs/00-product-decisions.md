## 2. 事件模型：一件事 = 标题 + 可选字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | 是 | **动作短语**，不是原话（如"跟张总开会"） |
| 时间 | 否 | 三种精度：仅日期 / 日期+时刻 / 时段（开始–结束）；允许"时段为主 + 截止点" |
| 重复 | 否 | 每天/每周/每月等 |
| 计数目标 | 否 | 次数 + 周期（如每天 3 杯） |

- 系统自动记录：创建时间、完成时间。
- 除以上外，**v1 不引入任何字段**（备注/标签/金额/父子/提醒时间等都不加）。
- **不存"类型"枚举**；一条事件是什么形态，由字段组合推导，显示模板决定怎么摆。
- 加字段的原则：只有某个显示或行为真的需要时才加，不预先堆字段。

---

## 3. AI 解析规则

1. **标题是动作**：AI 把口语改写成"要做什么"的动作短语；界面显示动作，不显示原话。
2. **按动作拆条**：一次语音里有多个动作就拆成多条，一个动作一条；一条里共用的明确时间，各条继承。
3. **只解析明确说出的内容**：日期、时刻、时段清楚才进时间字段；"晚上/上午/尽快"等模糊说法**不解析**，时间留空——说清楚是用户的责任。
4. **不猜、不补默认、不追问**：没说的字段就是空。
5. "提醒我"只作为时间线索；提醒字段已砍、**到点不发通知**。

## 4. 完成与消失

- 只有两种状态：**未完成 / 已完成**。"逾期/今天/以后"只是视图分组，不是状态。
- 完成动作：主窗口行首圆圈点击 = 完成；悬浮窗点击任务 = 完成；计数任务点一下 = +1。
- **已完成折叠在所有视图底部**（A/B、今天/全部都一样），**点击可恢复**。
- 单次 / 无时间的事：完成 → 24 小时内可撤销、可见 → **24 小时后物理删除**。
- 重复任务：完成的是"这一次" → 记一次完成 → **系列本身不删**，按重复规则下次再出现；本次记录 24h 后删除。
- 计数任务：看**周期边界**——"每天 3 杯"到**零点**清零，"每周 3 次"到**周一边界**清零；完成状态也在边界消失，下一周期从 0 开始。
- **删除**：在右侧详情抽屉里删除；**删除后不可恢复**（不设撤销）。
- 已完成项被"恢复"后回到未完成（细节见 §10）。

## 5. 显示模板与规则

只有两种模板，**数据同源，模板只决定摆法**：

### A 时间轴
- 主窗口：可切 **一天 / 7 天（周视图，7 列）/ 日历（月历网格）**
- 悬浮窗：**只有一天**
- 时间范围可配置：设置里**自由拖拽选区（像截图，框外变暗）**；主窗口与悬浮窗**各配一套**
- 选区边界撞到某个时段任务中间时，**自动把该任务完整包进来**，不能裁半条
- 时间点任务与时间段任务都显示在轴上；轴下方放"无时间/打卡"类事项
- 日历视图：格子显示已安排任务，只写"要做什么"，每格最多 3 个，**点击某天弹出当天清单**

### B 清单
- 可切换 **今天 / 全部**
- 主窗口通过视图切换；**悬浮窗里直接用小切换控件**（像切页面颜色）
- 一行一条：勾选圈 + 动作 + 时间文字

### 通用
- 已完成在底部折叠（所有视图），点击可恢复
- 悬浮窗是独立小部件：**可移动、可缩放**，要"足够精致"；不提供设置入口，只放一个**"进入软件首页"图标**；点任务 = 完成

## 6. 页面与跳转

- **主窗口 = 一个主页面 + 设置页**，不拆"今日/全部"两个页面
- 主页面：顶部 **A/B 视图切换**；点任务行 → **右侧详情抽屉**；行首圆圈 = 完成
- **不做首次启动引导**（打开即主页面）
- 设置页：主窗 A 的时间范围、悬浮窗设置、其他（待细化）
- 日历点某天 → 弹出当天清单（不跳页）
- 悬浮窗：独立窗口，见 §5

---

## 7. 操作与快捷键

- 捕捉：`Ctrl+Alt+Space` 弹出输入条；**默认开麦，也可以直接打字**；`Esc` 取消
- 显示/隐藏悬浮窗：`Ctrl+Alt+W`
- 详情抽屉可编辑：标题、时间、重复、计数；可删除（不可恢复）
- **不做数据备份与导出**：数据只在本机 SQLite；24h 物理删除后不可找回
- **不做系统通知**：到点不弹通知
- 悬浮窗创建入口（此前确认）：语音原地录、文字跳主窗口——需与"无收件箱"模型对齐（见 §10）

## 8. 视觉方向（初步）

- 关键词：**透明玻璃、极简、克制、留白、高级感、当代艺术品、晶莹剔透**

- 具体视觉（主窗/悬浮窗透明程度、强调色、深浅模式、字体、动效）见 §10 待细化

## 9. 沿用的外围决策（此前已确认）

- 平台：Windows 优先，macOS 以后
- 分发：先自用 + 小范围朋友，架构为公开预留
- AI 服务：官方轻量网关为主 + BYOK 兜底 + 规则模式
- 官方服务额度：邀请码 + 每设备每天 200 次 + 月预算 ¥200 告警
- 隐私：音频发语音识别厂商、文字发 DeepSeek；需在界面某处明示（无首启引导，具体位置待定）
- 名字：Clarify，公开前查商标
- 技术栈：Tauri 2 + React + Rust + SQLite；DeepSeek `deepseek-flash` 非思考 + JSON；ASR 默认候选阿里实时（spike 最终定）
- **不做**：系统通知、首次引导、数据备份/导出

## 10. 待定清单（未确认，不做默认）

1. 数据存储位置与数据库细节（无备份/导出后，数据安全策略）
2. 视觉细化：主窗/悬浮窗透明程度、强调色、深浅模式、字体、动效

5. 原始语音文本是否在软件内部保留、是否支持"重新解析"

13. 详情抽屉的字段清单与校验规则
14. 官方服务在界面里如何呈现（激活码、额度、服务状态）
15. 已完成折叠的交互细节（展开/收起、排序、恢复按钮位置）
16. 窗口/托盘/后台运行方式（不做通知后，托盘是否仍需要）
