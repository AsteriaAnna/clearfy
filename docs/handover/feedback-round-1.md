# 试用反馈第 1 轮：定位与修复（2026-11-01）

## 1. 悬浮窗“没反应、不显示要做的事”

### 定位到的根因（3 个）

1. **没有数据变更通知**：主窗/语音创建任务后，悬浮窗只在启动时 `listOpen()` 一次，之后不会刷新。
2. **A 模板过滤过窄**：只显示“今天 + 有具体时间”的任务；无时间、计数、明天的任务全部只体现在「还有 N 件」里，用户看不到。
3. **默认高度偏小**：300×220 时实际只能放 2 行（46 头部 + 44 底部 + 内边距），更容易让人觉得“没东西”。

### 修复

- Rust 所有写命令（create/complete/restore/increment/update/delete/ai_parse）统一 emit `clarify://changed`
- 主窗与悬浮窗都监听 `clarify://changed` 并重新加载
- 悬浮窗 A 模板改为：**今日任务优先，然后未来任务（显示 11-02 日期），无时间/计数任务也进入列表**
- 默认展开高度改为 260（可放 3 行），仍保留 300 宽、180–420 可调范围

## 2. 悬浮窗折叠/展开（豆包式符号）

- 头部新增「—」按钮：收起为 64×64 圆形符号（带未完成数量角标）
- 点击符号展开为原尺寸（记住收起前高度）
- 符号用自定义拖拽阈值：移动超过 4px 触发窗口拖动，未移动则点击展开
- 再次启动时保持上次折叠/展开状态

## 3. 移动/拉伸体验提示

- 头部 `cursor: grab` / 拖动时 `grabbing`，`title="拖动移动悬浮窗"`
- 底边常驻 26×2px 拖拽握把，hover 变宽变主题色；`cursor: row-resize`
- 收起/展开、语音中都有状态提示（正在听/正在识别/已安排 N 项）

## 4. 设置页

- **整块删除 AI Key 配置**（用户不需要配置；Key 编译进应用，内置直连）
- 返回按钮改为**右下角固定按钮**
- 新增「视图」区块：直接点 A 时间轴 / B 清单跳转
- 保留外观主题、窗口与退出、关于

## 5. 悬浮窗底部

- 「＋说一句」改为 **麦克风 + 笔** 两个图标
- 麦克风：直接在悬浮窗录音 → 豆包流式识别 → DeepSeek 创建；再点结束
- 笔：打开主窗口（Today）
- 右侧保留「还有 N 件 ›」

## 6. 代码组织梳理

修改压力主要来自两个 600+ 行文件；已拆分：

| 之前 | 之后 |
|---|---|
| `src/App.tsx` 682 行（状态 + 列表 + 设置 + 详情 + 录音 + 时间工具） | ~500 行，只保留主窗状态与布局 |
| — | `src/components/Settings.tsx` |
| — | `src/components/DetailDrawer.tsx` |
| — | `src/components/TimeMark.tsx`（TimeMark + Circle） |
| `src/lib/time.ts` | 时间/日期/事件判断共享工具（主窗 + 悬浮窗共用） |
| `src/lib/audio.ts` | PCM 录音与 base64 编码（主窗 + 悬浮窗共用） |
| `src/lib/theme.ts` | 主题定义 |
| `src/overlay/Overlay.tsx` 单文件 | 折叠/录音/刷新/列表均在同一组件，复用 lib |

后续可继续把 `src-tauri/src/lib.rs` 的窗口状态代码拆到 `window_state.rs`（低风险、纯搬运）。
