# 错误分类与用户文案（error-taxonomy）

- Owner：tech-writer（技术与工程文档）
- 版本：v0.1（初稿，待评审冻结）
- 更新日期：2026-11-01
- 状态：**v1 冻结候选**。所有代码（Rust / 前端 / 网关）必须使用本文错误码；用户可见文案以本文为准（UX 可调整措辞但不得改变语义/动作）。
- 关联：`05-contracts/tauri-ipc.md` §2（IPC 错误信封）、`05-contracts/gateway-api.md` §5（网关错误体）、`05-contracts/ai-json.md` §7（解析失败处理）、`04-architecture.md` §9（失败降级矩阵）

---

## 1. 原则

1. **一句话说清用户能做什么**：文案必须包含"发生了什么 + 你可以怎样"，不出现错误码、不出现堆栈、不出现英文技术词（`HTTP 502`、`JSON` 等不进 UI）。
2. **区分三类状态**（不许都叫"出错了"）：
   - **未就绪/未配置**（如没激活码、没填 BYOK Key、麦克风权限）→ 引导去设置；
   - **暂时不可用**（断网、超时、服务故障）→ 可重试/降级，安抚 + 可行动；
   - **不可用/需修改**（额度用尽、激活码吊销、组合非法）→ 说明边界与恢复时间。
3. **错误不阻塞捕捉**：任何 AI/网络错误都必须有降级路径（规则模式/文字输入/原文兜底），"把事记下来"永不失败（00-decisions §3/§7）。
4. **错误码只是契约**：UI 按 `code` 做逻辑，不解析 `message`；新增/改语义必须走 §10 流程。
5. **隐私优先**：错误日志不记录正文、音频、Key、激活码；用户可见信息不暴露内部端点/厂商细节。
6. **无系统通知**：所有错误只在本应用内呈现（捕捉条/主窗/设置页），不弹 Windows 通知（产品决策 §7）。
7. **可重试性以"重试是否有意义"定义**，不是以"是否网络错误"定义。

## 2. 错误信封

### 2.1 IPC（客户端内部）

```json
{
  "code": "CLR-E3005",
  "message": "转写服务暂时不可用，可直接打字",
  "retryable": true,
  "retry_after_ms": 300,
  "trace_id": "trace_01J9Z2M4Q8Y6T1V3W5X7Y9Z1B6",
  "detail": null
}
```

- `detail` v1 恒为 `null`；技术细节只进本地日志（`trace_id` 关联）。
- `retryable` 由 §4 的"自动重试"列推导（`auto_once`/`by_time` → true，其余 false）。
- 前端 `ipc.ts` 统一包装为 `IpcError(code, message, retryable, traceId)`。

### 2.2 网关（HTTP）

见 `gateway-api.md` §5：`{request_id, error:{code, message, retryable, retry_after_s, detail:null}}`。网关 `code` 是**网关内部错误码**（大写蛇形），客户端按 §6 映射为 `CLR-*`；两套码都不直接展示给用户。

## 3. 错误码规则

```
CLR-E<区域><3位序号>             例：CLR-E3005
区域：0=内部/未知  1=配置与凭据  2=网络与网关  3=转写与录音
      4=解析      5=本地数据/事件 6=系统/窗口/快捷键
```

- 错误码**只增不改、永不复用**；废弃码保留在文档并标注 `deprecated`。
- 新增码必须同时提供：中文文案、触发条件、可重试性、降级动作、日志级别、呈现位置（§10 流程 + PR checklist）。
- 严重度：
  - `error`：阻塞当前操作（需提示 + 可能的降级）；
  - `warning`：已自动降级/部分成功（轻提示，不打断）；
  - `notice`：信息（通常不弹，只写状态区/日志）。

## 5. 用户文案规范

1. **句式**：状态 + 可行动作；≤2 句；不用感叹号；不卖萌、不责备用户。
2. **降级时说清结果**："已用本地规则安排" 比 "AI 失败" 重要——用户关心事有没有记下来。
3. **额度类必须给恢复时间**："明天 0 点恢复"、"本月额度已用完"。
4. **配置类必须指路**："到设置 → AI 服务"（文案可带简单路径，不写内部字段名）。
5. **禁止**：错误码、英文技术词（HTTP/JSON/SQLite）、厂商名称堆砌、`undefined/null`、堆栈、请求 URL。
6. **不要暴露**：网关地址、激活码掩码之外的任何字符、设备 ID、数据库路径（设置页"关于"可展示版本与日志目录，属用户可理解信息）。
7. **无系统通知**：文案只在应用内出现；应用隐藏时后台错误进 `app.error` 事件，等用户打开主窗/设置页时呈现，不弹系统通知。

## 7. 降级动作矩阵（错误 → 系统行为 → 用户可见）

| 触发 | 系统动作（自动） | 用户可见（不阻塞） | 数据结果 |
|---|---|---|---|
| 官方不可用（网络/5xx/超时） | BYOK 已配置 → 本次切 BYOK；否则解析规则化 | 轻提示"已用本地规则安排"（或"已用自带 Key"） | 事项照常创建 |
| 官方额度/预算（429） | 当日/当月停官方；BYOK/规则 | 设置页/条内状态"官方额度已用完" | 事项照常创建 |
| 激活码无效/吊销（401） | 停官方；BYOK/规则 | 设置页错误 + 捕捉条提示 | 事项照常创建 |
| 断网 | 规则解析（文字）；语音禁用 | "网络不可用，可打字" | 文字事项照常创建 |
| 转写失败 | 转文字编辑（若有部分文本）；否则提示重说 | 捕捉条切文字模式 | 未创建（音频不落盘） |
| 解析失败（JSON/Schema/空） | 规则解析 → 原文兜底 1 条 | 轻提示 | 事项照常创建（标题可能为原文，§10-4 待确认） |
| 麦克风不可用 | 切文字模式 | 提示检查权限/设备 | 未创建 |
| 写库失败 | 保留 UI 输入；不乐观删除 | 错误提示 + 重试按钮 | 未保存（输入保留） |
| 设置写入失败 | 回滚内存旧值 | 设置页提示 | 设置不变 |
| 悬浮窗创建失败 | 仅主窗运行 | 主窗提示 | 不受影响 |
| 透明材质失败 | 自动降级 solid/低透明 | 首次提示（可关闭） | 不受影响 |
| 24 h 清理失败 | 下轮重试 | 无（折叠区稍晚消失） | 不丢数据 |
| 热键冲突 | 保留旧键/禁用该功能入口 | 设置页提示改键 | 不受影响 |

## 8. 重试与超时（与 tauri-ipc §8、gateway-api §8 一致）

| 类别 | 自动重试 | 退避 | 备注 |
|---|---|---|---|
| 网络/DNS/TLS 失败 | 1 次 | 300 ms | TLS 不重试（`E2003`） |
| 转写 5xx/超时 | 1 次 | 300 ms | 401/413/429 不重试 |
| 解析 5xx/超时 | 网关内部 1 次（JSON 校验失败）；客户端网络类 1 次 | 500 ms / 300 ms | 合计最多 2 次网络往返；`E4002/4003` 客户端不重试 |
| 额度/预算/激活 | 0 | — | 按时间点恢复（次日 00:00 / 作者调整） |
| 本地写（事件/设置） | 0（`op_id` 幂等） | — | 用户手动重试 |
| 本地读 | 1 次 | 100 ms | 仅 DB busy/传输错误 |

禁止：对同一错误叠加多层重试（网关 + 客户端 + 前端）；重试必须复用同一 `batch_id`（配额不重复计）。

## 9. 日志与脱敏

| 允许 | 禁止 |
|---|---|
| `code`、`trace_id`、模块、耗时、`event_id`（UUID）、`batch_id`、错误级别 | 正文/标题、转写文本、音频、激活码/Key（任何片段）、完整请求/响应体 |
| 用户操作类型（capture/complete/...） | 用户设备路径、端口、IP |

- 本地日志默认 `warn`；`debug` 只在开发构建可开。
- 错误详情（技术原因）只写本地日志，`error-taxonomy` 的 `code` 是唯一跨层标识。
- 任何新增日志点必须在 PR checklist 中确认不违反上表。

## 10. 新增/修改错误码流程

1. 在本文 §4 对应区域新增一行（码、名称、严重度、可重试、触发、文案、降级、日志）。
2. 代码中新增枚举值（Rust `AppErrorCode` / 前端镜像常量 / 网关错误码），前后端**同一 PR**。
3. 若涉及网关错误码：更新 `gateway-api.md` §5.2（网关码）与 §6 映射（客户端码）。
4. 增加测试：至少一个触发路径的单元/集成测试；文案快照测试（前端 i18n）。
5. 不得删除/复用旧码；废弃码标注 `deprecated` + 替代码。
6. 用户文案变更需同步 `02-ux-spec.md` 文案表（若该表维护同一句）。
7. 契约文档变更记录表更新版本。
