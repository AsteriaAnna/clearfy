**分层约定**
1. 能用单元测试覆盖的规则，不允许只靠 E2E 证明；E2E 只证明"链路通 + 用户可见行为"。

4. 不 mock 被测规则本身：时间解析、周期推进、清理判定、视图查询过滤在测试中必须走真实实现。
5. 测试使用**可注入时钟**；禁止用真实 `sleep` 等待 24h / 跨天（见 §3.3）。
6. 无专职 QA：开发自测为主，Lead 按 §7 手测清单抽查验收；AI 代理可执行自动化用例与报告，但**不得自评通过**。

### 3.3 时间控制（本策略的关键可测性前提）

1. 业务代码通过 `Clock`（或等价注入接口）取"现在"；测试注入固定/可推进时间。**这是 M1 开工前必须写进 `04-architecture.md` 的架构约束**（§3.4；当前 04 未明确，列为 M0-02 红队修复项）。
2. 前端测试用 Vitest fake timers；Rust 测试用注入时钟（两者可结合，不依赖真实等待）。
3. 24h 清理判定期望（A-07-04）：
   - 界面可见窗口 = `[completed_at, completed_at+24h)`；**不得早于 24h 删除/消失**；
   - 删除发生在下一轮清理（≤24h+60min+5min 余量）；清理前后界面与数据同阈值，不出现"界面消失但库还在被其他视图查到"；
   - `completed_at` 写入规则：系统时钟回拨时 `completed_at = max(now, created_at)`（03 U21）。
4. 周期边界判定期望：每天本地 00:00:00；每周本地周一 00:00:00（ISO 周键 `YYYY-Www`，含跨年 2026-W53 → 2027-W01）；读路径懒重置 + 清理兜底。
5. 额外边界：23:59:59 完成、跨年（12/31→1/1）、闰年（2/28→2/29→3/1）、系统时钟**回拨**（不提前删除）与**前拨**（按新 now 判定，可能提前清理——03 U25 接受）、应用关闭跨边界再启动、睡眠/休眠唤醒后补扫、改系统时区（03 U22：UTC 时刻不重算，显示随新时区；计数按新时区重判，可能立即重置）。
6. 所有时间断言写"绝对时刻 + 时区/UTC"，不写"现在之后 N 小时"的模糊断言。

## 8. AI 评估集与跑分（L4，强制门禁）

> 数据集与指标定义以 `docs/eval/README.md` 为准（样本与 README 在 `docs/eval/`；可执行 runner 与跑分结果在仓库根 `eval/`，见 `08-engineering.md`）。跑分分两类：① **规则解析跑分** `pnpm eval:rules`（确定性、每次 PR、门禁 <60s）；② **AI 解析跑分** `pnpm eval:ai`（云端、手动/夜间/发版，需测试 Key 与成本上限）。本节规定**何时跑、怎么判、怎么留档**。

### 8.1 指标与达标线（以 `docs/eval/README.md` §5 为准）

| 指标 | 定义要点 | 达标线 |
|---|---|---|
| JSON 合法率（首次） | 第一次响应即通过（语法+Schema+语义校验） | 62/62（99%×62=61.38，61/62=98.4%<99%，故按整数判定必须全过） |
| JSON 合法率（重试后最终） | 重试后仍非法→兜底，不得进生产 | 100%（62/62） |
| 时间字段准确率 | 按对齐动作计（日期/时刻/时段字段） | ≥ 90% |
| 不幻觉率 | 幻觉动作 = 0（无原文依据新增时间/动作） | 100%（硬红线） |
| 拆分 F1 | micro F1（跨句累加） | ≥ 0.80 |
| 动作标题保真 | macro 相似度（不只看人工抽样） | ≥ 0.85 |
| 周期/计数准确率 | repeat + count 字段 | ≥ 95% |
| 解析 P95 | 单次 AI 请求 wall-clock（不含网络排队） | ≤ 3000 ms |
| 端到端 P95 | 捕捉停止→落库可见（含 ASR+网络，由性能测试覆盖） | ≤ 4000 ms（Charter） |
| 兜底率 | LLM 最终失败→规则/原文兜底的句数占比 | ≤ 2% |
| 单次成本 | 按厂商现价折算 | < ¥0.02 |
| 分类覆盖 | 62 条九分类每类 ≥1 条 | 数据完整性 |

**明确要求**：评估集中必须包含"模糊词时间留空""共享时间继承""无时间基准的重复不解析""无上下午钟点只解析日期"四类样本；幻觉统计必须基于 transcript 语言依据（ai-json R3/R4/R7）。分类时间准确率 <70% 时不单独卡门禁但必须标红并人工复核。

### 8.2 强制跑分触发条件

**规则解析**：每次提交（`pnpm eval:rules` 离线门禁）。**AI 解析**：
1. 修改任何 AI prompt / 系统提示词 / few-shot；
2. 更换模型名、模型版本、厂商、JSON 模式参数、temperature 等采样参数；
3. AI 契约（`05-contracts/ai-json.md`）或解析字段变更；
4. 网关 `/v1/parse`、`/v1/transcribe` 逻辑/上游适配变更；
5. 发布任何版本（M3 起每个里程碑末与发版前）；
6. 每两周一次例行回归（即使无变更，用于捕捉上游模型漂移）。

### 8.3 跑分 Runbook（开发执行）

1. 冻结评估集版本（记录 `docs/eval/` 的提交哈希；`sentences/expected` 不可随意改，改集需 Lead 批准并升版本）。
2. 用测试网关/真实网关（**记录网关版本与模型名**）跑 runner，输出原始响应 JSON。
3. 自动计算指标 + 列出失败样本（含输入、期望、实际、错误类型）。
4. 人工复核失败样本（至少全部时间字段错误 + 20% 其它）。
5. 与基线比较：时间准确率下降 >2pp 或拆分 F1 下降 >0.05 → 告警并暂停合并；报告需含 `docs/eval/README.md` §7.3 规定的 report JSON。
6. 结果写入 `eval/runs/<YYYYMMDD>-<model>-<prompt-version>.md`：日期、模型版本、prompt 版本、样本数、指标表、失败清单、结论、操作人（CI 夜间跑分由 bot/PR 更新）。
7. 不达标处理：runner 退出码 `1`（门禁不达标）不得合并该 prompt/模型变更（网关侧 feature flag 保持旧版本）；退出码 `2`（数据集/配置错误）/`3`（认证/额度错误）先修复环境。Lead 决策是否改默认模型或默认走规则模式。
8. 每次跑分记录成本（样本 token × 单价），确认 < ¥0.02/次 预算假设。

### 8.4 数据集治理

- 评估集是**唯一质量标尺**：不得为了让指标好看而修改期望值；确需修改必须 Lead 审批、记录原因、升版本并全量重跑（规则见 `docs/eval/README.md` §8）。
- 数据集当前 **62 条九分类**（下限 ≥50）；新增能力必须补对应正例/反例；训练/调 prompt 用的样本与验收样本分离（若后续扩充到 100 条，划分 dev/holdout，holdout 不参与调参）。
- 声音/文本样本匿名化；不存真实姓名、电话、地址等敏感信息。
